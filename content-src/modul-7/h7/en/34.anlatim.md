### What you will learn in this lesson
- The idea of defence in depth (layered defence)
- What six defences stop and what they do not
- Why never giving secret information to the model is the strongest measure
- That choosing a set of defences on a limited budget is an engineering balance

### What you should know first
Lesson 33: prompt injection, direct and indirect attacks, the fragility of blacklists. Lesson 8: the system message. Lessons 26-30: tool permissions.

### One lock is not enough
A house's safety is not left only to the door lock: there are also windows, an alarm and neighbours. **Defence in depth** means that if one layer is broken through, the next one steps in. In AI systems too, a single move is never enough.

### Six layers
```
Data/instruction separation   Label the document: "this is data"
Instruction hierarchy         The system rule ranks above the document
Output filter                 Remove secret data and suspicious links
Least privilege               Do not give the model secrets or unneeded tools
Human approval                Get approval before a risky action
Banned word list              Helps partly, easy to get round
```
The table in the workshop is simplified for the lesson; which measure stops which attack really depends on the situation. Still, it is good for seeing the structure. For example, if only the banned word list is chosen, five of the six attacks stay open, because the list only catches the direct attack.

### The limit of an output filter
Writing an output filter is easy:
```
def cikti_suz(metin):
    return metin.replace("KIRMIZI-42", "***")
```
`"Kod: KIRMIZI-42"` is cleaned, but if the attacker makes the model write the code backwards, `"24-IZMIRIK"` does not look like the text the filter is looking for, and it gets through. The filter is useful, but it is not enough on its own.

### The strongest principle
A model cannot tell what it does not know. If you write a secret key in the system message, every successful injection reveals it. Never give the key to the model; call a secure service when you need it. In the workshop this measure is expensive (cost 3), because the application has to be designed again from the start; but in real life it is often the best investment.

### Balance
Putting in all six layers is also a cost: slowness, harder use, maintenance work. The goal is to choose a set that fits the budget and covers different types of attack. In the workshop it is possible to stop all six attacks with three layers and a total cost of 3.

### Summary
Security does not come from a single move; it comes from layers. Every layer has a cost and a gap. The soundest measure is never to give secret information to the model. Some risk always remains; writing that honestly in the report is also part of engineering.
