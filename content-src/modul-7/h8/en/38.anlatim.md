### What you will learn in this lesson
- How to approach the question of whether a robot's decision should be made by a rule or a model
- Why a rule is predictable and testable
- How an "if" condition stops the robot, and how the threshold is chosen
- Why a safety rule must live independently of the model

### What you should know first
It is enough to know that an agent calls tools and sees the result (lessons 26-29), and to know tools such as `mesafe()` and how to use `$son`. We will come back to the idea of human oversight in lesson 39.

### Making decisions in a robot
A robot does two jobs: it senses (sensors, camera), and it decides and acts (motors, brakes). The decision can be made in two ways:

```
Rule:   if distance < 50 cm, stop
Model:  camera image -> learned system -> "there is an obstacle" prediction
```

A rule is **predictable**: same input, same result. It can be tested, and its reason can be explained. A model, on the other hand, is very useful for jobs that are hard to write as a rule (is there a person in an image?); but it can be wrong, and it is hard for it to say why.

### Which one, and when?
| Job | Suitable approach | Why |
|---|---|---|
| Stop if too close | Rule | Safety; it must behave the same way every time |
| Is there a person on the camera? | Learned model | Very hard to write as a rule |
| Speed limit | Rule | A hard limit, no bargaining |
| Understanding the command "go to the kitchen" | Language model | Natural language |

In most real systems the two work together: the model makes a suggestion, and the rule has the last word.

### Threshold and safety margin
When you choose a threshold, take into account the distance the robot needs to stop. Suppose the wall is 100 cm away, the robot takes 20 cm steps, and after each step it measures and stops if what remains is below 50 cm. The remaining distance after the steps: 80, 60, 40. On the third step 40 < 50, and the robot stops having moved 60 cm. If the threshold is chosen too small, the robot gets too close to the wall; if the step is large, it can "jump over" the threshold.

### How does this work in the virtual robot?
In the agent loop in the workshop, the script is **your rule**. The tools really run: the robot moves forward, and if it hits the wall, it crashes. The script and the tools are deterministic; the same script gives the same result every time. An `eğer` ("if") line runs the call if the condition is true. Careful: `$son` is the result of the latest successful call. If `dur()` succeeds, `$son` is no longer the distance but `durdu` ("stopped").

### If the model says "forward"
Even if a language model translates the command, the rule "do not hit the wall" should not be inside the model. Hard limits live in a layer that is separate from the model and runs after it. Whatever the model says, that layer blocks the command.

### Summary
A rule is predictable, testable and explainable; it is the first choice for safety decisions. A model is used for jobs that cannot be written as rules, such as sensing, but it can be wrong. Choose the threshold based on the step size, and keep an eye on the value of `$son`. A safety limit must run in a layer independent of the model.
