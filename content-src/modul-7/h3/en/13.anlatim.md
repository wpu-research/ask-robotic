### Steps first, then the answer
Instead of giving the answer to a hard question "in your head" in one go, writing the intermediate steps lowers the margin of error. This idea is used for models too. The model produces its answer token by token, and every token it writes goes into the context of the next token. If you have it write intermediate steps before the answer, the final answer is built on those steps. This is called **chain of thought**. It often improves the result in multi-step calculation and logic questions; some models also do this themselves, with a separate "thinking" stage.

### How do you ask for it?
Fix the format:
```
Solve the question step by step.
First write the working under the heading "Steps:".
On the last line, write only "Answer:" and the number.
```
Having the answer on a separate line matters for a program. For example, code that finds the answer line and pulls out the number does not mix it up with the intermediate numbers in the steps.

### A small example
Question: "Each robot has 4 servos. How many servos are needed in total for 6 robots and 5 spare servos?"
```
Steps: 6 robots x 4 servos = 24 servos. 24 + 5 spares = 29.
Answer: 29
```

### Limits
- **Fluent does not mean correct.** The steps look logical, but a multiplication mistake in the first step is carried all the way to the end. The model may have written each step without really "checking" it. The written steps may also not be an exact record of what goes on inside the model.
- **Cost.** A long answer means more tokens and more time. An answer with a chain can be ten times longer than one without.
- **It is unnecessary for simple questions.**
- **If an exact result is needed**, the model should not do the calculation: a tool such as a calculator is called. In lesson 26 you will build this yourself.

### This is a reading lesson
There is no Workshop tool in this lesson. No model answer is simulated either; the example above is a hand-written example, not the output of a real model.

### Summary
Chain of thought means having intermediate steps written before the answer; each step becomes the context of the next. Fixing the format and having the final answer written on a separate line makes the program's job easier. Steps looking fluent does not guarantee they are correct, so check them. For exact calculations, using a tool is safer.
