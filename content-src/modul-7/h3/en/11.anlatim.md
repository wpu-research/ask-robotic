### A rule, or an example?
Instead of explaining the "positive or negative" game to a friend at length, you show them two examples: "I loved the lesson: positive. I didn't understand a thing: negative." The same approach works for language models. A prompt that gives only instructions is called a **zero-shot** prompt, and a prompt that shows a few examples together with the instructions is called a **few-shot** prompt.

### What does the model learn from an example?
While reading the prompt, the model catches patterns: the names of the labels, the length of the output, a fancy or plain tone. The examples sit inside the context window (lesson 7). So the model does not "learn and store" anything; it reads the examples again with every request and continues the pattern. That is why few-shot prompting is not the same as **fine-tuning**, which changes the model's weights. Examples also take up tokens: if one example is 25 tokens, three examples take 75 tokens of the context.

### What does a good example look like?
```
Classify the comment: positive or negative.
Input: I really loved the robot lesson.
Output: positive
Input: The circuit just wouldn't work.
Output: negative
```
- **Balanced:** give at least one example of each label. If they are all "positive", the model may tend to say "positive" to everything.
- **Consistent:** the same format, the same way of writing the label. Do not write "positive" in one place and "Positive :)" in another.
- **Correct:** an example with the wrong label teaches the model the wrong pattern.
- **In line with the instructions:** if the instructions say "write only the label" while an example contains a long explanation, the model cannot know which one to follow.

### What does the checker in the Workshop do?
The **Prompt checker** is not a model and does not produce answers. It counts the "Input:" and "Output:" patterns; it cannot know whether the examples are of good quality. On a real model, you decide the effect of the number and order of examples not by feel, but with the eval measurements you will learn in week 4.

### Summary
A few-shot prompt adds input-output examples to the instructions; the model catches the pattern from the examples. The examples should be balanced, consistent and correct. This method does not train the model: the examples go into the context with every request and use tokens. A checker counting the examples does not prove that the examples are good.
