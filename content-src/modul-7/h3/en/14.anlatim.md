### Iterate like an engineer
The first attempt is rarely the best. An engineer runs the code, sees the error, and fixes it. With prompts the loop is the same:
1. Write the goal: what does a good answer look like?
2. Write the first prompt (v1).
3. Judge the result against the goal.
4. Change **one** thing (v2).
5. Try again and compare with v1.

### Why one change?
If you add a role, a format and a constraint all at once, the score may go from 30 to 90; but you cannot know which one worked. With a single change, cause and effect are visible. If a change does not work, you can undo it. Write it down on paper or in a file:

| Version | Change | Check score | Note |
|---|---|---|---|
| v1 | "Summarise the announcement." | 20 | Only the task is there |
| v2 | The sentence "Write the summary as at most 3 bullet points." was added | 50 | One sentence brought both the format and the limit |

### Two different measures
The **checklist score** is the number the Workshop checker gives. It looks at keywords and is not a model; it cannot know whether a version is bad. **Real success** means trying the prompt on a model with example inputs and counting the correct answers. You can do this with a small list:
```
const sonuclar = [true, false, false, true, true, false, true, true]
const dogru = sonuclar.filter((s) => s).length
console.log(dogru / sonuclar.length * 100)
```
`filter` keeps only the ones that are `true`; `length` gives the count. Here there are 5 correct out of 8 attempts, and the rate comes out at 62.5 per cent. A version can have a higher score but a lower real rate; in week 4 you will measure this with evals.

### How do you work in the Workshop?
There is no model answer in the Workshop. After each change, only the check score changes. So the discipline you learn in this lesson (one change, keeping a record) is real, while the score itself is only a hint.

### Summary
Improving a prompt is a loop: write, try, judge, change one thing. Save the versions. The checklist score is a useful hint, but not proof; the proof is the rate of correct answers measured on real examples.
