### What you will learn in this lesson
- What an eval (evaluation) is and why it is needed
- The two parts of a test case: the input and the expected output
- How to work out accuracy: the number correct divided by the total cases
- Why measuring with easy cases is misleading

### What you should know first
This week is a new topic; but it will help to remember the ideas of prompts and outputs you saw in lessons 1-15. It is especially important to know that a system may not always give the same answer to the same input (lesson 6, temperature).

### "Seems to work" is not a measurement
You wrote a prompt, tried it three times, and the answers look good. This gives you a feeling; but it does not show it will also work on a hundred different inputs. In engineering, feelings are turned into measurement. This is called **evaluation**, or **eval** for short.

### How is an eval set up?
An eval is made of three parts:
- **Test case:** an input and the **expected output** you accept as correct for that input.
- **System:** the thing you are measuring (a model, a prompt or a small program).
- **Measure:** comparing the system's answers with the expected ones and turning them into a number.

The simplest measure is **accuracy**:

```
accuracy = cases found correctly / total cases
```

For example, if 6 out of 8 cases are correct, the accuracy is 6 / 8 = 0.75, or 75%.

### This week's system is not a model
The classifier in the Workshop is **not** a real language model. It is a small, hand-written, rule-based program that labels comments as positive, negative or unclear: it looks at lists of positive and negative words, and the word `değil` (not) flips the meaning of the word before it. Why did we choose this? Because you can follow its behaviour exactly. The method (write cases, run them, measure), however, is the same as the one used to measure a real model.

### Where does the system go wrong?
The rule-based system has two known weak points:
- **Sarcasm:** in the sentence `Harika, yine bozuldu` (Great, it broke again) the system sees only the word `harika` (great) and says positive. For a person the sentence is negative.
- **Unknown word:** in the sentence `Fena değil` (Not bad), because `fena` (bad) is not in the list, `değil` finds nothing to flip; the system says unclear. A person would say "positive".

If you write only easy sentences such as `Bu uygulama çok güzel` (This app is very nice), the accuracy comes out high and you never see these weaknesses of the system. The value of an eval is in showing where the system goes wrong.

### Summary
An eval measures a system with cases whose expected outputs are known in advance. Accuracy is the ratio of the number of correct cases to the total cases. This week's classifier is a small rule-based program, not a real model; but the method of measuring it is real. Easy cases mislead; hard cases show the system's weak points.
