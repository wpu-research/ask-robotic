### What you will learn in this lesson
- The features of a good test case
- Why you need examples of every label (positive, negative, unclear)
- How a repeated case distorts the measurement
- How to check labels with someone else

### What you should know first
Lesson 16: evals, test cases, expected output and accuracy. Remember that the classifier is a small rule-based program and not a real model.

### A case is like a question
A good exam has easy and hard questions, and questions whose answer is beyond argument. A test set is the same. For each case, ask yourself: "Would two people give this sentence the same label?" If they would not, the case is unclear, and saying the system "got it wrong" makes no sense.

### Use all three labels
The sentiment classifier gives three labels: **positive**, **negative**, **unclear**. The unclear label is very important in real life, because most texts carry no feeling. Calling the sentence `Toplantı saat beşte` (The meeting is at five) positive or negative is a mistake. If the set has no unclear cases at all, you can never find out whether the system makes this mistake.

Writing at least one easy and one hard case for each label is a good start:

```
positive  : "Harika bir proje"        (easy)  /  "Fena değil" (hard)
negative  : "Çok yavaş ve sıkıcı"     (easy)  /  "Harika, yine bozuldu" (hard)
unclear   : "Ders salı günü"          (easy)  /  "Hızlı ama kullanışsız" (hard)
```

(In English: "A great project" / "Not bad"; "Very slow and boring" / "Great, it broke again"; "The lesson is on Tuesday" / "Fast but useless".)

### A repeated case inflates the measurement
If you write the sentence `Güzel` (Nice) three times, the system collects three points from the same easy case. However many cases you have, repeats teach you nothing new. The tool marks repeated cases; what matters is the number of **unique** cases.

### A wrong label is a mistake too
Sometimes it is not the system but the expected label you wrote that is wrong. If you accidentally write "negative" for the sentence `Süper ve eğlenceli` (Great and fun), a system that works correctly looks as if it "got it wrong". So give your first cases to a friend and label them separately. Every case you disagree on should either be fixed or taken out of the set.

### Summary
A good case is clear: two people give it the same label. A good set contains easy and hard, positive, negative and unclear cases in balance, and has no repeats. The labels themselves must be checked too, because a wrong label looks like a system error.
