### What you will learn in this lesson
- Why a count-based vector cannot link synonyms
- Which mistake this limit causes in a search system
- Simple fixes such as query expansion
- Which idea learned vectors (embedding models) are based on

### What you should know first
Lesson 21: word count, TF-IDF and cosine similarity. Lesson 2: splitting a text into pieces.

### Same word or same meaning?
To a person, `mesafe` and `uzaklık` (both mean "distance") are the same thing. In a count vector, though, they are two separate columns. If your query only has `uzaklık` and the document only says `mesafe`, there is no shared term. With no shared term, the cosine is 0.

```
query:     "uzaklığı nasıl bulur"  -> terms: uzakl, bulur
document:  "... mesafeyi hesaplar" -> terms: mesaf, hesap
shared terms: none  ->  similarity = 0
```

### What does stemming fix, and what does it not?
The stemming in the workshop only keeps the first five letters of a word. That way `mesafe` and `mesafeyi` ("the distance") become the same term (`mesaf`). But `uzak` (far) and `mesafe` still stay separate, because the problem is meaning, not spelling. So stemming is only a partial fix. A simple rule can also backfire: two different words with the same first five letters can be merged by mistake.

### Which mistake happens?
This limit mostly leads to **missing the relevant document**: the user is looking for the right document but sees no result at all. The system does not notice, because "0 results" is a valid answer. In RAG systems this is more serious: if the retrieval step cannot find the right chunk, the model never sees the right information.

### Simple fixes
- **Query expansion:** when the word `ödev` (homework) comes in, `görev` (task) and `proje` (project) are added too. You write the synonym list by hand.
- **Better stemming:** a real Turkish analyser splits off the suffixes.
- **Learned vectors:** **embedding models** are learned from huge amounts of text and place texts that are close in meaning on close vectors. This lets texts with no shared words match too. The method in the workshop does not do this; it was chosen on purpose so you can see the limit.

### Summary
A count vector only matches identical terms. With synonyms the similarity comes out 0 and the relevant document is missed. Query expansion and better stemming help partly. The real fix is embedding models, which have learned to encode meaning as numbers.
