### What you will learn in this lesson
- Why an agent needs a step limit
- How a failed tool call comes back as an observation
- How to work out the total movement in advance when using `tekrar N:` ("repeat N")
- The stopping conditions: result, error, limit

### What you should know first
Lessons 26-27: tool calls, observations, carrying results with `$n`. Addition and multiplication are enough.

### Why do you need to know when to stop?
An agent that does not stop is both expensive and dangerous. Every step costs time and (in a real service) money; a badly built loop can do the same thing for ever. That is why a good agent has three ways to stop:

- **Result:** the job is done, `bitir(...)` was called.
- **Error:** a problem with no way back happened (for example a crash).
- **Limit:** the number of steps reached the upper limit. In the workshop the limit is 30.

### An error comes back as an observation
A failed tool call does not crash the program; the error text comes back to the agent as an observation. The agent can read it and try something different. But irreversible outcomes are a different matter: once the robot hits the wall there is no "try again", and in the workshop the agent stops there.

### The virtual corridor: calculate first
The robot is heading towards a wall 100 cm away. `ileri(n)` returns the remaining distance. If the script is `tekrar 3: ileri(20)`, the movement goes like this:

| Call | Remaining distance |
|---|---|
| ileri(20) | 80 |
| ileri(20) | 60 |
| ileri(20) | 40 |

In total 3 × 20 = 60 cm; there are 40 cm to the wall, which is safe. If you write `tekrar 6: ileri(20)`, the 100 cm is completed on the fifth call and the robot **crashes** into the wall. The sixth call never runs. The rule of the lesson: multiply out the total of the repeat before you run the script.

### The step limit is a safety net
Even if you write `tekrar 99:`, the workshop limits the repeat on one line to 30, and once the total number of steps reaches 30, the next tool call gives a "step limit exceeded" error. If you write `tekrar 99: hesapla(1)` on its own, the line ends after 30 steps, and because there is no other call after it, the error message may not appear; only the list of 30 observations is left. The limit cuts off an endless loop, but it does not show that the plan is right. The limit is the last resort; the real safeguard is a correctly calculated plan.

### Summary
An agent stops when it finishes the job, when it gets an error, or when it reaches the step limit. A failed call comes back as an observation; but irreversible outcomes such as hitting the wall must be prevented by calculating in advance. When you use `tekrar`, multiply out the total movement and compare it with the wall. The step limit is the last safety net against an endless loop.
