### What you will learn in this lesson
- The four parts of the agent loop: think, act, observe, done?
- The difference between a chatbot and an agent
- How to chain the results of `ara()` and `hesapla()` with `$1`, `$2`, `$son`
- Where a scripted agent differs from a real agent

### What you should know first
Lesson 26: tool calls, observations, carrying results with `$1`. For the idea of retrieving information, Lessons 23-25 (RAG) are useful.

### Not one answer, but a loop
A chatbot answers a question in one go. An **agent**, however, builds a loop towards a goal:

| Step | Question | In the workshop |
|---|---|---|
| Think | What is the next step towards the goal? | You choose the line in the script |
| Act | Which tool should I call, with which input? | `ara(...)`, `hesapla(...)` |
| Observe | What did the tool return? | The "Observation" column |
| Done? | Is the answer ready? | If yes, `bitir(...)`; if no, back to the start |

### Example: how many groups will there be in the club?
Question: number of members ÷ group size. In the small, hand-made knowledge base in the workshop, the number of members is 24 and the group size is 4.

```
ara(üye sayısı)          # observation: 24
ara(grup büyüklüğü)      # observation: 4
hesapla($1/$2)           # observation: 6
bitir($3)                # answer: 6
```

Four steps were taken. If you had written `$son`, you would have got the latest successful result. If you search for something that is not in this knowledge base (`ara(yıldız sayısı)`, "number of stars"), the answer is `bulunamadı` ("not found").

### Changing the plan based on the observation
The power of a real agent is that it looks at the observation and changes its plan: if a search gave no result, it tries another query. The script in the workshop, however, is written in advance; the lines do not change by themselves based on the observation. The thought texts in the ready-made "scripted demo" were also written by hand; no model produced them. Knowing this limit is an honest engineering habit.

### Checking the observation
The script does not notice by itself that a step gave an error. If you write `hesapla($1*2)` after `ara(yıldız sayısı)` has failed, the calculator gets the text `bulunamadı` instead of a number, and the second step gives an error too. In agent design, every observation needs to be asked "did it work?".

### Summary
An agent repeats the think-act-observe loop until it is done. Results are carried from one step to another with `$1`, `$2`, `$son`. The tools in the workshop are real, but the part that decides is you; in a real agent the model decides and can change its plan based on the observation. Using a failed observation without checking it leads to a chain of errors.
