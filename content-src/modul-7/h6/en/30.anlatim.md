### What you will learn in this lesson
- How to plan an agent that measures twice and moves forward twice
- How to number each step and refer to it with the right `$n`
- How to predict the project's numbers in advance and check them with the script
- The difference in reliability between a scripted agent and an agent that uses a model

### What you should know first
Lessons 26-29: tool calls, `$n`, `mesafe`, `ileri`, `dur`, the safety margin. Also the idea of evaluation (eval) from Week 4: we judge a system not by one try, but by measuring it again and again.

### Write the plan on paper first
Project: the wall is 100 cm away. The agent measures, moves forward half the remaining distance, measures again, moves forward 60 per cent of what remains and stops. Before writing the script, number the steps and work out the result:

| Step | Call | Observation |
|---|---|---|
| 1 | mesafe() | 100 |
| 2 | hesapla($1*0.5) | 50 |
| 3 | ileri($2) | 50 (remaining) |
| 4 | mesafe() | 50 |
| 5 | hesapla($4*0.6) | 30 |
| 6 | ileri($5) | 20 (remaining) |

In the end the robot has moved 80 cm and is 20 cm from the wall. The project criterion is stopping between 5 and 20 cm from the wall, so 20 cm is on the limit and is accepted.

### The most common mistake: the wrong number
In the script, `$4` is the second measurement and `$1` is the first measurement (100). If you write `$1*0.6` by mistake in the fifth step, you get 60 cm; the robot has already moved 50 cm, so `ileri(60)` crashes it into the wall. This also shows you why two measurements are needed: the second calculation must be based on the distance remaining after the first move.

### Script versus model: the difference in reliability
In the workshop you are the "model step"; because the script is fixed, it always gives the same result in the same world. In a real agent a language model makes the decision and can choose different steps even on the same task. That is why agents are measured over many tries, not one: in how many did it reach the goal, in how many did it crash? If you run the same agent 10 times and see a crash in 3, you do not say "it works"; you find the type of error and add a safety layer (rule-based braking, approval).

### Writing the report
In the report, write the script, the observation of each step, why you measured twice, and the safety measures you would add if you connected it to a real robot. The results in the workshop are virtual; on a real robot there is also sensor noise and delay.

### Summary
The mini agent project applies the measure-calculate-move loop twice. Working out the plan on paper first and using the `$n` numbers correctly is half the battle. The script in the workshop reaches the same result every time; an agent that uses a model may not, so repeated measurement and a safety layer are needed.
