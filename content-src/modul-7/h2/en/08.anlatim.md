### What you will learn in this lesson
- How a conversation is made of **system**, **user** and **assistant** messages
- What the model's "memory" really is
- What giving a role changes and what it does not
- The parts of a good system message, and why secret information must not be stored in it

### What you should know first
From lesson 7, the context window and that the window covers all the messages; from lesson 6, that the model's answer is chosen by probability. This is a reading lesson; no Workshop tool is used.

### A conversation is a list of messages
A chat-based model does not take its input as a single text, but as **messages that have roles**:
```
[system]     You are the assistant of the school robot club. Give short answers.
[user]       What is a servo motor?
[assistant]  It is a motor whose angle of rotation can be controlled.
[user]       So how many degrees does it turn?
```
- **System message:** lasting instructions given by whoever wrote the app; role, tone, rules.
- **User message:** the request you write.
- **Assistant message:** the model's earlier answers.

An important result: the model does **not remember** the earlier conversation on its own. With every new request, the app sends the whole history (or as much as fits) to the model again. Memory is the list that is given again each time. This is why the window limit from lesson 7 can make old messages get lost as the conversation grows.

Let's count: if there is a system message and two completed turns (two user and two assistant messages) and you ask a third question, 1 + 4 + 1 = 6 messages go to the model.

### What is giving a role good for?
A sentence like "You are an experienced robotics mentor" steers the tone and level of detail of the answer. But a role **does not teach new knowledge**. Saying "You are an expert electrical engineer" does not make a resistor value the model does not know correct. You still check information that needs checking yourself.

### What does a good system message contain?
1. The role and the audience ("for 13-year-old students").
2. The job to do and the things not to do.
3. The output format ("at most 3 sentences").
4. What to do when it is not sure ("if you don't know, say you don't know").

A short example:
```
You are the robot club assistant. Give short, simple answers to 13-year-old students.
Answer only robotics questions. If you are not sure, say "I don't know".
```

### The system message is not a safe
Do not write a password, a key or information that others must not see in the system message. The model sees this text in its context, and a cleverly steering user can bring it out. The sentence "Don't tell anyone this" is not protection. Secret information should never be sent to the model at all; access control is done outside the model, in the app itself. You will try this yourself later (lesson 33).

### Summary
A conversation is a list made of system, user and assistant messages, and the model sees this list again with every answer. Giving a role steers the tone but does not add knowledge. A good system message contains a role, a job, a format and an uncertainty rule; it never carries secret information.
