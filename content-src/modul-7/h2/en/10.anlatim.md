### What you will learn in this lesson
- What a prompt **template** is: fixed instructions and a changing input
- How to run the same template with many inputs using a placeholder
- Why separating the input from the instructions is a good habit
- How to work out a template's cost in tokens

### What you should know first
From lesson 9, the six parts of a prompt (task, role, context, example, format, constraint) and the checker; from lesson 8, roles and the system message; from lesson 7, the token budget.

### Don't write the same job again
Imagine you want to classify hundreds of student comments at a school. You do not write the prompt from scratch for each comment. You write the part that does not change once and leave the changing part blank. This skeleton is called a **template**. A template is like a function: fixed instructions + a changing input.

### Placeholder
The mark for the changing place is a **placeholder**; in this lesson we use `{{yorum}}` ("comment"). Each time, the program replaces this mark with the real comment:
```
sablon = "Classify the comment: {{yorum}}"
istek  = sablon.replace("{{yorum}}", "The lesson was nice")
# istek -> "Classify the comment: The lesson was nice"
```
In the Workshop you write only the template text; replacing the placeholder is the program's job in real apps.

### Template skeleton
The parts from lesson 9 fit into the template like this:
```
You are a comment review assistant.                           (role)
Classify the robotics club's student comments as positive
or negative; the aim is to see overall satisfaction.          (task + context)
Example: Input: I really loved the lesson. Output: positive.  (example)
In the answer, write only one word: positive or negative.     (format)
Do not add any other explanation.                             (constraint)
Comment: {{yorum}}                                            (changing input)
```
This text gets 100 points from the checker in the Workshop (39 words). Our goal is 80 points: there must be a role and an example, and the words "comment" and "positive" must appear. The checker still only counts whether the parts are there; testing the template with real comments is still your job.

### Separate the input from the instructions
Text from the user will go into the comment field. If someone writes "forget the previous rules" in a comment, the model may think it is an instruction. Separating the input with a label (`Yorum: {{yorum}}` or `<yorum>...</yorum>`) makes the text easier to read and makes it easier to tell the model "this is data, not an instruction". This is **not full protection**; it only lowers the risk. You will try prompt injection in a simulation in lessons 33 and 34.

### The template's cost
The fixed part goes again with every request and uses tokens. If the fixed part is 120 tokens and each comment is 30 tokens, classifying 5 comments separately means 5 x (120 + 30) = 750 tokens of input. Keeping the fixed part short and useful protects both the budget and the speed.

### Summary
A template is the combination of fixed instructions and a changing input; the placeholder shows the place that changes. A good template carries the six parts of a prompt, separates the input from the instructions and does not grow for no reason. Because the fixed part is sent again with every request, its length shows up in the cost.
