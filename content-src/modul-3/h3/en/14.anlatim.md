### map: from range to range
`map(x, girişMin, girişMax, çıkışMin, çıkışMax)` moves a number in proportion. The formula:

```
(x - inMin) * (outMax - outMin) / (inMax - inMin) + outMin
```

Example: `map(500, 200, 800, 0, 100)` = 300 × 100 / 600 = 50. It has two features: it is integer maths (everything after the decimal point is thrown away, 116.67 → 116), and if the input is outside the range, the output overflows the range too.

### constrain: fix the limits
`constrain(x, alt, üst)` keeps x between `alt` (low) and `üst` (high). It is used together with `map`: first `map`, then `constrain`. `map(100, 200, 800, 0, 100)` gives −16; `constrain(−16, 0, 100)` gives 0.

### Calibration
The same sensor works in different ranges in different places. In **calibration**, the sensor is watched for a while when the program starts, and the smallest and largest values seen are saved. The starting values are chosen the opposite way round: `enAz = 1023`, `enCok = 0`; this way the first measurement updates both. If the range becomes too narrow, the `map` division breaks, so a minimum difference (for example 50) is enforced.

### Smoothing
`analogRead` wobbles a little even in the same light; this is called **noise**. There are two simple methods:

```
ort = toplam / 16;                   // average of 16 measurements
duzgun = duzgun * 0.9 + ham * 0.1;   // exponential smoothing
```

Averaging reduces noise, but the reading takes longer (16 measurements × 3 ms ≈ 48 ms). With exponential smoothing, a new value has an effect slowly.

### Summary
`map` moves a range in proportion, works with whole numbers and does not limit the result; `constrain` clips the result. Calibration learns the sensor's real range when the program starts. Averaging and exponential smoothing reduce noise, and in return they make the response a little slower.
