### What you will learn in this lesson
- Why a real button **bounces** and which bug this causes
- The difference between a **level** and an **edge**
- How to store the previous state in a variable and catch the falling edge
- How to get "one press, one action" behaviour with a simple **debounce** method

### What you should know first
`digitalRead`, `INPUT_PULLUP` and "pressed = LOW" from lesson 6; `if`, `&&` and `!=` from lesson 7; `delay` (milliseconds) from lesson 3.

### Buttons bounce
When a button closes, the two metal parts inside it hit each other and spring back. The contact opens and closes for a while, and for a few milliseconds the pin goes back and forth between HIGH and LOW. The board sees all of this because it reads thousands of times a second. A single press might be read like this:

```
Expected : HIGH HIGH HIGH LOW  LOW  LOW  LOW
Real     : HIGH HIGH LOW  HIGH LOW  HIGH LOW  LOW
```

The button in the lab gives a clean signal, so bounce is not modelled. The method you learn here protects you from bugs when you move to a real button.

### Level and edge
"Is the button pressed right now?" is a **level** question, and it gives the same answer on every pass. "Was the button pressed just now?" is an **edge** question, and it is true only at the moment of change:

| Change | Name | Meaning (INPUT_PULLUP) |
|---|---|---|
| HIGH to LOW | falling edge | the button was pressed |
| LOW to HIGH | rising edge | the button was released |

If you are making a counter or an on-off switch, you must use the edge, not the level. If you hold the button down, the level stays LOW for thousands of passes, but the falling edge happens only once.

### Remembering the previous state
To find the edge you need two values: the current reading and the reading from the previous pass. You keep the previous value in a variable defined outside `loop()`, so that it is not wiped when the pass ends. At the end of every pass you update the variable by writing `onceki = simdi;`. If this line is forgotten, the board always compares with the old value and sees the same edge again and again.

```
if (onceki == HIGH && simdi == LOW) {
  // falling edge: pressed just now
}
onceki = simdi;
```

### Debounce
Because of bounce, a single press produces more than one falling edge. For example, if three edges are counted, an on-off LED flips three times and the result becomes unpredictable. **Debounce** is the method of "I saw a change, but let me wait a short time and look again": when a change is noticed, you wait about 20 ms, read the pin again, and if the change is still there it counts as real. The bounce when you release goes through the same check.

The waiting time is a trade-off. If it is too short, you read before the bounce is over. If it is too long (for example half a second), you miss quick presses in a row, and the board cannot look after anything else during this time, because nothing runs during a `delay`. 20 to 50 ms is enough for most buttons.

### Summary
Real buttons bounce when they close, and a single press can produce several edges. A level describes a state, and an edge describes a change; counting jobs need the falling edge. You find the edge by storing the previous state in a variable, and you filter out bounce with a short wait and a second reading.
