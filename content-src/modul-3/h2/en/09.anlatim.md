### What you will learn in this lesson
- How the board and the computer talk through the serial port, and what the **baud** rate means
- How to print values to the screen with `Serial.print` and `Serial.println`
- How to read a command from the computer with `Serial.available()` and `Serial.read()`
- How to pick out the number inside a command with `Serial.parseInt()`

### What is serial communication?
The board and the computer talk over the USB cable by sending bits **one after another** (in series). Both sides must talk at the same speed; this speed is called **baud**. We always use 9600 baud. If a different speed is chosen in a real Serial Monitor, meaningless characters appear on the screen. At the start, `Serial.begin(9600);` is written once inside `setup()`.

### Printing
`Serial.print(x)` writes the value and leaves the cursor on the same line. `Serial.println(x)` writes and moves to the next line. For text you use double quotes; for numbers and variables you write the value directly. This is the easiest way to debug: you see the answer to "did the code reach this point, and what value does the variable have?" in the serial monitor.

```
Serial.print("D2 = ");
Serial.println(digitalRead(2));   // on screen: D2 = 1
```

Turkish letters (`ç, ğ, ı, ö, ş, ü`) are not used in printed texts, because they may look garbled in the serial monitor.

### Reading
The bytes coming from the computer line up in a buffer on the board. `Serial.available()` gives the number of bytes waiting to be read; 0 means nothing is waiting. `Serial.read()` takes one byte from the buffer. You must check with `available()` first; otherwise `read()` returns -1 when there is no data.

A single character is stored in the `char` type and written with **single quotes**: `'A'`. `"A"` in double quotes is a piece of text and cannot be compared with a `char`. Capital and small letters are different characters: `'A'` and `'a'` are not equal.

### Parsing
The incoming text often has the form "command + number", for example `B3`. Splitting this text into meaningful parts is called **parsing**. First you take the command letter with `read()`, then `Serial.parseInt()` reads the next number as an `int`. If the serial monitor adds "Newline", `B3` actually sends three bytes:

| Order | Character | Meaning |
|---|---|---|
| 1 | B | command |
| 2 | 3 | digit of the number |
| 3 | line ending | shows that the message has ended |

The line-ending character is read with `read()` on the next pass, but it is ignored because it matches no command. If you read the number with `read()`, you get the character code, not the digit itself; use `parseInt()` for numbers. If no data comes after the number, `parseInt()` waits about one second and gives up.

### Summary
The serial port is a two-way conversation between the board and the computer, and both sides' baud rates must be equal. `print` and `println` print, `available` and `read` read the incoming command, and `parseInt` picks out the number in the command. Single characters are written with single quotes, and capital and small letters are different.
