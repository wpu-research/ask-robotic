### What you will learn in this lesson
- How to **split a big project into parts** and think about each part separately
- Why the **state variables** (`sayac`, `onceki`) that are the program's memory are defined outside `loop()`
- How to combine edge detection, debounce, `bool` and serial commands in one program
- How to work out the response time of a program that uses `delay`

### What you should know first
`INPUT_PULLUP` and "pressed = LOW" from lesson 6; `if`, `bool`, `&&` and `!` from lesson 7; edge detection and debounce from lesson 8; `Serial.print`, `available()` and `read()` from lesson 9; `digitalWrite` and `delay` from lesson 3.

### Plan first, then code
The doorbell project looks like a single job, but it is really the sum of five small jobs. Writing down in a table which lesson each job comes from makes the program easier to write:

| Job | What it does | Source |
|---|---|---|
| Reading | Reads the bell button with `INPUT_PULLUP` | Lesson 6 |
| Press detection | Catches the falling edge and filters out bounce | Lesson 8 |
| Response | Lights the LED, sounds the buzzer, increases the counter | Lessons 3, 7 |
| Silent mode | The buzzer stays quiet if the mute button on D3 is pressed | Lesson 7 |
| Reporting | Prints `Zil: N`; handles the `S` and `R` commands | Lesson 9 |

Filling in this table first and trying each row separately is much safer than writing everything in one go.

### The program's memory
`sayac` holds how many times the bell has rung, and `onceki` holds the button's previous state. These two variables are defined outside `loop()`. `loop()` starts again from the top on every pass; a variable defined inside it is created again on every pass and reset to its starting value (for example 0). A variable defined outside keeps its value as long as the program runs. `sayac++` means `sayac = sayac + 1`.

### Putting the parts together
Press detection is done inside `loop()` with two nested `if`s: first it checks whether there is a change, then it waits 20 ms and checks whether the change is real. If it is real and the new value is LOW, the bell button has been pressed. For silent mode you write `bool sessiz = (digitalRead(3) == LOW);`, and the buzzer is sounded only when `!sessiz`: that is, "if not silent". The LED lights in every case.

An active buzzer has its own sound generator inside: it beeps when you give the pin HIGH and goes quiet when you give it LOW. Its legs have a direction: the + leg goes to D8 and the - leg to GND. In the lab, do not forget to set the part's type to Active.

### The cost of waiting
During a `delay` the board cannot look at anything else. While a press is being handled, the 20 ms debounce wait and the 300 ms ring time run one after the other: for about 20 + 300 = 320 ms the program is as good as frozen. This time is acceptable for a bell, because incoming serial commands wait in the buffer and are read afterwards. Much longer waits, however, make the project sluggish; in the coming weeks you will learn timing without using `delay`.

### Summary
A big project is split into small jobs with a plan table, and each job is solved with a pattern from earlier lessons. State variables defined outside `loop()` are kept from pass to pass. Edge detection and debounce make sure a press is counted only once. You can work out a program's response time by adding up its `delay` times.
