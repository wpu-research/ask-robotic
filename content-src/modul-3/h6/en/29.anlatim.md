### When the phone rings
Whatever you are doing, when the phone rings you stop, answer it, talk, and then carry on from where you left off. An **interrupt** is the same idea. When an event happens on a chosen pin, the processor pauses what it is doing, runs a small function called an **ISR** (interrupt service routine), and goes back to the main program. It works even inside a `delay`; so there is almost no risk of missing a short event.

### Which pins on the Uno?
On the Uno, external interrupts are only on two pins:

| Pin | Interrupt |
|---|---|
| D2 | INT0 |
| D3 | INT1 |

Setting it up: `attachInterrupt(digitalPinToInterrupt(2), basildi, FALLING);` The mode sets the type of event: `FALLING` is a drop from HIGH to LOW (a button press with INPUT_PULLUP), `RISING` is a rise from LOW to HIGH (a release), and `CHANGE` is both. With `CHANGE`, one press and release produce two interrupts.

### ISR rules
- **Keep it short.** Increase a counter or raise a flag; let `loop()` do the real work.
- **Do not use `delay()` or `Serial.print`.** Time does not flow inside an ISR, and the program gets stuck if the output buffer fills up.
- **Take no parameters, return no value.** An ISR is a `void` function with no arguments.
- **Against button bounce**, add a guard of a few tens of milliseconds.

### volatile and atomic reading
A variable shared between the ISR and `loop()` is marked **`volatile`**. It tells the compiler: "this value can change outside the normal flow of the program, check memory every time". If you leave it out, `loop()` may use an old copy and the counter seems never to go up. The Uno has an 8-bit processor; a 2-byte or 4-byte variable is read in two to four steps. If an interrupt arrives right in the middle, you read half a value. That is why you take a copy after `noInterrupts();` and turn them back on with `interrupts();`.

### Timer: regular interrupts
**Timer1** inside the board counts by dividing the 16 MHz clock. If the prescaler is 256, that gives 16 000 000 / 256 = 62 500 ticks per second. When the counter has counted N+1 ticks for the compare value `OCR1A`, an interrupt arrives:

```
interrupt interval = (OCR1A + 1) / 62 500 seconds   (prescaler 256)
```

For `OCR1A = 31249`, 31 250 / 62 500 = 0.5 s. Timer1 uses the same unit as `analogWrite` on pins 9-10 and `Servo`; if they are used together, they clash.

### Summary
An interrupt is the mechanism that pauses the main program and runs a short ISR when an event happens. On the Uno it is set up on pins D2 and D3 with `attachInterrupt`. The ISR must be short; a shared variable must be `volatile`, and if it is several bytes long, interrupts must be turned off while it is read. For a timer interrupt, the interval is worked out with `(OCR1A + 1) / tick rate`.
