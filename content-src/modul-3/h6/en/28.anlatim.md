### What you will learn in this lesson
- Thinking of a program as **states** and **transitions**
- Naming states with `enum` and running the code for that state with `switch`
- Tying a transition to an event (a button) or to a time running out (`millis`)
- Restarting the time counter when the state changes

### What you should know first
`if` and `switch` from lesson 7; detecting the edge of a press from lesson 8; `millis()` and the `simdi - son >= aralik` pattern from lesson 27.

### Why a state machine?
A lift cannot be "door open" and "going up" at the same time; at any moment it is in one particular state. If you organise a program like this, your code stays readable. A **state machine** (FSM) keeps the **state** the program is in right now in a variable and defines the **transitions** between states. Order takes the place of tangled piles of `if`s.

### Draw first, then write
A traffic light has three states. First draw the diagram on paper:

```
[KIRMIZI] ---after 3 s---> [YESIL] ---after 3 s---> [SARI]
    ^                                                  |
    +--------------------after 1 s---------------------+
```

Each box is a state and each arrow is a transition. The text on the arrow is the **event** that triggers the transition: a button press or a time running out. The code is a one-to-one translation of the drawing.

### enum and switch
**`enum`** gives names to numbers: when you write `enum Durum { KIRMIZI, YESIL, SARI };`, KIRMIZI = 0, YESIL = 1, SARI = 2. Writing `durum = YESIL;` in the code is much easier to read than writing `durum = 1;`.

`switch (durum)` runs only the `case` block of the current state in each round. Each block does three jobs:
1. It sets the outputs for that state (which LED is on).
2. It checks the transition condition (is the time up, was the button pressed).
3. If the condition is met, it writes the new state and resets the time counter.

```
case KIRMIZI:
  digitalWrite(13, HIGH);
  if (simdi - durumBasi >= 3000) { durum = YESIL; durumBasi = simdi; }
  break;
```

The **`break;`** at the end of the block is a must. If you forget it, the program also runs the code of the state below (this is called "fall-through").

### Changing by time and by event
A transition can happen in two ways. In a timed transition you ask `simdi - durumBasi >= duration`; if you do not write `durumBasi = simdi;` when the state changes, the new state ends at once, because the difference is still based on the old value. In an event transition you look for the button's **edge** (a new press); otherwise a button held down jumps to the next state every round. For a mode cycle, the expression `(mod + 1) % 3` produces the sequence 0, 1, 2, 0, 1...

### Summary
A state machine keeps the state the program is in in an `enum` variable and uses `switch` to run the code for that state. Transitions are tied to time (`millis`) or to an event (a button edge); when the state changes, the time counter is reset, and every `case` ends with `break;`. Draw the diagram first, then code it.
