### The board's clock
**`millis()`** gives the milliseconds that have passed since the board was switched on. It is 0 when the program starts and goes up by 1 every millisecond. Think of a kitchen timer: you do not stand over the boiling egg, you glance at the clock now and then. With `millis()`, the program glances at the clock now and then while it is busy with other jobs.

### The pattern: look, compare, update
```
unsigned long simdi = millis();
if (simdi - son >= aralik) {
  son = simdi;      // saati yenile
  // işi yap
}
```

`son` (last) holds the moment you last did the job. `simdi - son` is the time that has passed since then. If that time has reached `aralik` (the interval), do the job and update `son`. There is no waiting anywhere in this code; if the condition is not met, `loop()` goes straight back to the start.

### Why does it not block?
With this pattern, `loop()` runs thousands of times a second. In every round, both the button and the clock are checked. The 2000 ms gap between looks from the previous lesson is now a few hundred microseconds; short presses are not missed.

### Each job has its own clock
If two LEDs are to blink at different speeds, give each one its own variable:

```
unsigned long son1 = 0;   // LED 1 için, aralık 1000 ms
unsigned long son2 = 0;   // LED 2 için, aralık 300 ms
```

If you use one shared `son`, when the first job updates the variable, the second job works out its own time wrongly. A small to-do table makes the job clear:

| Job | Interval | Variable |
|---|---|---|
| Toggle LED 1 | 1000 ms | `son1` |
| Toggle LED 2 | 300 ms | `son2` |
| Check the button | every round | (no clock needed) |

### Overflow: when the counter goes back to zero
The value of `millis()` is of type **`unsigned long`** (largest value 4 294 967 295). It reaches this number in about 49.7 days and wraps back to 0. If you use `int`, the largest value on the Uno is 32 767, so it overflows in about 32.8 seconds. Variables that hold times must always be `unsigned long`.

The safe pattern is **subtraction**: `simdi - son >= aralik`. With unsigned numbers, subtraction gives the right difference even when the counter wraps back to zero. For example, if `son = 4 294 967 000` and the counter wraps round to `simdi = 10`, the difference comes out as 306 ms. `simdi >= son + aralik` is wrong: `son + aralik` overflows and wraps round to a small number, and the program says "time is up" before it really is.

### Summary
`millis()` is the board's clock. The pattern `simdi - son >= aralik` asks "is the time up?" without waiting; `loop()` runs fast and each job works independently with its own `son` variable. Time variables must be `unsigned long` and the difference must be worked out by subtraction; that way the 49.7-day overflow causes no trouble.
