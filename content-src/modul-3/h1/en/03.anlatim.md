### What you should know first
From lesson 1, `setup()` and `loop()`, HIGH and LOW; from lesson 2, why an LED needs a series resistor.

### Blink, the "hello world" of hardware
When you learn a new language, the first program you write prints "Hello world" on the screen. In hardware, the equivalent is making an LED **blink**. It is called **Blink**. It looks small, but it contains the basics of programming and of circuits.

### A circuit is a loop
For current to flow, it needs a closed path: Uno pin → resistor → the LED's anode (A) → the LED's cathode (K) → GND. If the path is broken anywhere, the LED does not light up. An LED **has a direction**: current only passes from A to K. The resistor protects the LED; its value is 330 Ω (lesson 2).

### The program: four commands
```
pinMode(13, OUTPUT);     // make pin 13 an output
digitalWrite(13, HIGH);  // give the pin 5 V
digitalWrite(13, LOW);   // give the pin 0 V
delay(1000);             // wait 1000 ms
```

- `pinMode(pin, OUTPUT)` sets the pin's **direction**. You write it once inside `setup()`.
- `digitalWrite(pin, HIGH/LOW)` sets the pin's **state**.
- `delay(ms)` makes the program wait in **milliseconds**. 1000 ms = 1 second.

### Order matters
The board runs the commands from top to bottom, **in order**. When `loop()` reaches the end, it goes back to the very start. In Blink the order is: switch on, wait, switch off, wait, start again. The waiting times set how long the LED stays on and off. If it is on for 1000 ms and off for 1000 ms, one full cycle takes 2000 ms.

### Common small mistakes
- If you forget the `;` at the end of a command, the compiler gives an error.
- If you do not write `pinMode`, the pin does not become an output; the LED glows very dimly or not at all.
- If the LED is connected the wrong way round, it does not light up. Making mistakes is safe here: you can stop with ■ and fix it, or start again with ↺.

### Summary
Blink brings three things together: a correctly built circuit, `pinMode` to set the pin's direction, and `digitalWrite` and `delay` to drive the pin and wait. The commands run in order, and `loop()` repeats all the time.
