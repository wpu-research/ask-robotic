### Plan first, then code
When a project is big, you do not start writing code straight away. First you write down the states:

| State | When | What happens |
|---|---|---|
| Waiting | Button released | The blue LED slowly brightens and fades |
| Playing | Button pressed (LOW) | The tempo is read, the melody plays, every note lights up in its own colour |
| End | The melody ends | The LED goes off, the waiting breath carries on |

Circuit: buzzer on D8, RGB LED on D9 (R), D10 (G), D11 (B), button on D2 (`INPUT_PULLUP`), potentiometer on A0.

### Splitting the work into functions
Every small job becomes a function. `loop()` only makes decisions:

```
loop()
 ├─ is the button pressed?
 │    yes → tempoOku() → melodiCal(bpm)
 │                          └─ for every note, notaCal(f, duration)
 │                                ├─ notaRengi(f) → renkAyarla(r, g, b)
 │                                └─ tone + delay
 │    no  → bekleNefesi()
```

Thanks to this structure, when something goes wrong you only look at the small function involved. The `melodi[]` and `uzunluk[]` arrays (melody, and how many beats) are defined as global, because many functions use them.

### Working out tempo and length
`tempoOku()` turns the potentiometer reading into beats per minute with `map(analogRead(A0), 0, 1023, 80, 200)`. One beat lasts `60000 / bpm` milliseconds:

| Pot position | bpm | Beat | Melody (16 beats) |
|---|---|---|---|
| All the way to the GND side | 80 | 750 ms | 12 000 ms |
| Middle (reading about 512) | 140 | 428 ms | 6 848 ms |
| All the way to the 5 V side | 200 | 300 ms | 4 800 ms |

The melody has 14 notes, but because two notes last 2 beats, the total is 12 × 1 + 2 × 2 = 16 beats.

### Limits and rules
- The blue channel is on D11. While `tone` is playing, you only write 0 or 255. That is why the blue values in the note colours are either fully on or fully off.
- In a `switch`, every `case` ends with `break;`; otherwise the code falls through into the next `case` and the colour gets mixed up.
- While `delay` is running, the program does not run any other command. During the melody you cannot watch the button or the pot. The solution will come in later weeks.

### Summary
You first split the project into states (waiting, playing, end), then turn each state into a small function. `loop()` only makes decisions. The tempo is chosen with the potentiometer between 80 and 200 beats per minute, and the beat length is 60000 / bpm. While `tone` is playing, only fully on/off is used on D11. Because of `delay`, the inputs are not watched during the melody.
