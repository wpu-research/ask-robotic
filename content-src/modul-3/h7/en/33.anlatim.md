### What you will learn in this lesson
- That the I2C bus is made of two wires (SDA and SCL), and which pins they are on the Uno
- What a device address is and why it is needed
- Converting hexadecimal (0x) notation to decimal
- Scanning addresses with `Wire` and using a display with `LiquidCrystal_I2C`

### What you should know first
The LCD's parallel connection and its need for 6 pins from lesson 32; bytes and hexadecimal notation from lesson 31; the `for` loop from lesson 4.

### Why are two wires enough?
In lesson 32 you used 6 signal pins for one display. **I2C** ("eye-squared-see") does the same job with two wires:
- **SDA:** the data wire
- **SCL:** the clock wire, which sets the rhythm of the bits

On the Uno, SDA is on pin **A4** and SCL on pin **A5**. You cannot connect them to other pins; the hardware I2C is only on these two pins. Several devices can be connected to the same two wires. This is called a **bus**.

### Address: who is talking?
Everyone on the bus hears the same wires. The board writes an **address** at the start of the message; only the device with that address answers, and the others stay quiet. The address is a 7-bit number and is usually written in hexadecimal. In hexadecimal each digit is worth 16 times the one to its right:

```
0x27 = 2 × 16 + 7  = 39
0x3F = 3 × 16 + 15 = 63   (F = 15)
```

The address of I2C LCD modules is usually 0x27 or 0x3F. If two devices have the same address they get mixed up; the solution is to change the address jumpers (or, in the lab, the address property).

### Address scan
To find a device whose address you do not know, you try all the addresses one after another:

```
Wire.beginTransmission(adres);
byte hata = Wire.endTransmission();
```

`endTransmission()` returns an **error code**. `0` means "the device at the address answered". Any other number means there is a problem; in a scan its general meaning is "there is no device there". The scan program tries every address from 1 to 126 and prints those that return `0`. `Serial.println(adres, HEX)` prints the number in hexadecimal; if you do not write HEX, you see the decimal form, such as 63.

### Using it with a library
`Wire.begin()` connects the board to the bus. For the I2C LCD, the `LiquidCrystal_I2C` library is used as well:

```
LiquidCrystal_I2C lcd(0x27, 16, 2);   // adres, sütun, satır
lcd.init();
lcd.backlight();
```

The `print` and `setCursor` commands are the same as in lesson 32. What is different is that the object takes an **address** instead of pins, and that the display is started with `init()`. If you write the address wrongly, the display does not answer.

### Summary
With I2C a device is connected with only the SDA (A4) and SCL (A5) wires, and every device has an address on the bus. If you do not know the address, you find it with the scan program: if the result of `endTransmission()` is 0, the device is there. The address you write in the code must be the same as the device's; also take care not to connect 3.3 V devices to a 5 V bus.
