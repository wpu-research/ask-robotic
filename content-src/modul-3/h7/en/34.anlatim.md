### Three separate memories
The Uno's brain has three separate stores:

| Memory | Size | What does it hold? | When the power is cut |
|---|---|---|---|
| Flash | 32 KB | The program itself | Stays |
| SRAM | 2 KB | Variables while running | Erased |
| EEPROM | 1 KB | Permanent settings | Stays |

Variables such as `int sayac`, `float sicaklik` and `String` are in SRAM. They are all lost when the power is cut. Data that must be remembered, such as the thermostat's target temperature, is written to the EEPROM.

### Reading and writing the EEPROM
The EEPROM is 1024 bytes; each byte is at an **address** (0-1023). A cell that has never been written holds **255**.

```
byte a = EEPROM.read(0);     // 0. adresi oku
EEPROM.update(0, 24);        // yalnız değer farklıysa yaz
```

`read` and `update` are for a single byte. A `byte` holds at most 255; if you write `EEPROM.write(0, 300)`, the number is saved as 300 − 256 = 44. For data bigger than one byte there are `EEPROM.put(adres, değer)` and `EEPROM.get(adres, değer)`: an `int` takes 2 bytes and a `float` 4 bytes. A **struct** with several values takes as many addresses as its total size; you must write the next data after it.

### Wear and how to work it out
An EEPROM cell has a lifetime of about **100,000** writes; reading does not shorten it. Worked example: if you write to the same cell once every 10 seconds, 100,000 × 10 = 1,000,000 seconds, so the lifetime runs out in about 11.6 days. That is why:
- Do not write on every `loop` pass.
- Use `update` instead of `write`; if the value is already the same, it does not write at all.
- Write once after the user has finished adjusting the setting.

### SRAM and String
SRAM is only 2048 bytes. Every variable and every `String` takes space from here. `String` is handy, but if it keeps growing and shrinking in a program that runs for a long time, it can break SRAM into pieces. A fixed-size `char` array is safer. Writing text with `F("...")` leaves fixed text in Flash: `Serial.println(F("Merhaba"));`.

### The library pattern
This week you used three libraries. They all follow the same pattern: add it with `#include`, create an object if needed, and call it with `nesne.komut()` (object.command). The best way to learn how to use a new library is to look at its ready-made examples.

### Summary
Flash holds the program, SRAM the running variables, and EEPROM the permanent settings. You write to the EEPROM only when needed and with `update`, because every cell has a lifetime of about 100,000 writes. An empty cell reads as 255; do not mistake it for a valid value. SRAM is small, so use `String` carefully.
