### Goals for the week
By the end of this week the learner can:
1. Explain what an event is; use the A, B and A+B button event blocks.
2. Show the difference between pressed, released and long pressed; use the logo as a source of events.
3. Make a variable, set its value, make it bigger and smaller and show it on the screen (a counter).
4. Write a program that makes decisions with the random number block and **if ... then**; say what the difference between assignment and comparison is.
5. Build a scoreboard with three buttons, variables and a melody by following a rules table.

### Plan for the week
The week has five lessons; each lesson takes about 20-35 minutes. The plan is for one lesson a day. If you want a busier timetable, you can combine lessons 1 and 2, or lessons 3 and 4.

| Day | Lesson | Time | What you do |
|---|---|---|---|
| 1 | The A, B and A+B buttons | ~20 min | Read the explainer, give three icons to the three buttons, do the released and pause experiments, do the mini quiz. |
| 2 | Counter and variable | ~25 min | Build the visitor counter; watch the two-digit number by pressing 12 times; make it count in fives. |
| 3 | Electronic dice | ~25 min | Roll the dice once and put it in the box; show a heart on a 6; count how many sixes come up in 10 rolls. |
| 4 | The logo, long presses and secret buttons | ~20 min | Build the logo and long press blocks; measure the 1-second time by watching it yourself. |
| 5 | Project: Dice game scoreboard | ~35 min | Write the rules table, build the program, play the game with a friend, assess it with the rubric. |

### Prerequisite check
This week, the learner needs to be able to do these things from the end of week 1:
- Use the ▶ Run, ■ Stop and ↺ Reset buttons on the virtual card.
- Attach blocks inside header blocks such as **on start** and **forever**.
- Know the **show icon**, **show number**, **pause** and **clear screen** blocks.
- Do the basic operations (addition, subtraction, multiplication) comfortably; the counter and total sums use them.

### Concept map
- **Event:** event block (header block) → button A, B, A+B → pressed, released, long pressed (1 second) → logo (touched, released)
- **Data:** variable (a box with a name) → set to, change by → starting value → counter → total (accumulator)
- **Decision:** random number (both ends included) → comparison (=, ≠, <, ≤, >, ≥) → if ... then → else
- **Project:** rules table → zar and toplam → play melody (waits until it is over) → resetting

### Common mistakes
- **Not changing the button list.** A stays selected in both blocks; nothing happens when B is pressed.
- **Pressing A, then B, and expecting A+B.** To press both at the same time, use the A+B button underneath the virtual card.
- **Leaving a block outside the header block.** It looks faded and does not run.
- **Changing the variable and forgetting to show it.** The box changes, but nothing happens on the screen.
- **Showing first, then adding.** The counter is always one behind.
- **Using two separate random blocks.** The number shown on the screen and the number compared turn out different; roll the dice once and put it in the box.
- **Mixing up assignment and comparison.** "set to" puts a value in the box; "=" asks a question.
- **Mixing up `>` and `≥`.** 5 > 5 is false; 5 ≥ 5 is true.
- **Pressing for less than 1 second for a long press.** The event never comes.
- **Forgetting to reset the total.** In a new game, it adds on top of the old score.

### End-of-week review
1. Look at the concept cards of each lesson once more and read the "common mistake" lines out loud.
2. Read the explanations of the questions you got wrong in the mini quizzes again, then do the question again.
3. Build the counter program from scratch, without looking; then press A 12 times and describe what you see on the screen.
4. Add a rule to the dice program: a sad face on a 1, a heart on a 6. Make both branches with **if**.
5. Answer in your own words: "Without variables, how would the card keep track of the number of visitors?"

The mini quizzes of the five lessons are enough as the end-of-week test; 5 questions in each lesson, 25 questions in total. Goal: at least 4 correct in each lesson. Go back to the explainer of any lesson that needs more work.

### Project rubric (Dice game scoreboard)
| Criterion | Developing | Secure | Advanced |
|---|---|---|---|
| Events | One of the buttons does not react | A, B and A+B work correctly | An extra event has been added (such as resetting with a long press) |
| Variables | The total does not add up, or the last roll is always shown | zar and toplam are used correctly, A+B resets | A third variable has been added (such as the highest roll) |
| Dice and decision | There are two separate random blocks, or no melody plays on a 6 | The dice is rolled once, the victory melody plays on a 6 | There is an extra rule (reset when a 1 comes up, a happy face when it goes over 30) |
| Plan | There is no rules table | There is a table of events, jobs and variables | The table matches the program exactly |
| Explaining | Cannot explain what they did | Explains each button's job step by step | Explains how they found a mistake |

### Note for parents and teachers
- **Aim.** The big ideas of this week are "the card waits and runs when an event comes" and "the box remembers". There is no need to make them memorise anything; the learner sees it by trying things out on their own counter and dice.
- **How can you help?** When they get stuck, instead of giving the answer, ask: "Which block runs when you press which button?", "What is in the box right now?", "Are you showing this number on the screen, or did you only change the box?"
- **Probability.** The dice is random; in 10 rolls there may be no 6 at all. This is not a bug. Talking about how the share gets closer to one in six as the number of rolls goes up makes a good conversation.
- **Sound.** For the victory melody, the browser waits for a click on the page. If you cannot hear any sound, look at the Speaker section in the right panel.
- **Time.** Spreading the lessons out helps learning stick. Project day may run long; it is fine to leave it half-finished.
- **Safety.** Everything on this platform is virtual; no real parts, batteries or wires are needed.
- **Progress.** Mini quiz results are shown by skill on the "My progress" page (draft/pilot feature; only saved if consent was given).
