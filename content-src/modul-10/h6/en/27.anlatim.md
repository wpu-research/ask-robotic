### Every shake is an event
The accelerometer in a real step counter feels small jolts while you walk. On the virtual card, we count a shake as a step. The **when card is [shaken]** hat block runs once on every shake. If you put **change adim by 1** inside it, adim ("step") goes up by one on every shake.

### Equal or greater?
To do something when the goal is reached, we write a condition. A small change makes a big difference:

| Condition | adim = 9 | adim = 10 | adim = 11 | adim = 12 |
|---|---|---|---|---|
| adim = 10 | false | true | false | false |
| adim >= 10 | false | true | true | true |

"adim = 10" is only true on exactly the 10th step, so the celebration happens once. "adim >= 10", however, is true on every step after the 10th, so the celebration repeats on every shake. If the goal is to be done once, choose equality; if it is to be done "always after passing the goal", choose greater-than-or-equal.

### Every 10 steps
If you want to celebrate at 10, 20, 30... steps, the **remainder of adim ÷ 10** block is useful. The remainder is the number left over from a division:

| adim | remainder of adim ÷ 10 |
|---|---|
| 7 | 7 |
| 10 | 0 |
| 23 | 3 |
| 30 | 0 |

If the remainder is 0, adim is a multiple of 10. So the condition "if remainder = 0, celebrate" is true once every 10 steps.

### Where should the counting go?
You count first, then you check. If the counting block goes inside the **if**, it only counts while the condition is true. If the condition is "adim = 10" and adim starts at 0, the condition is never true, because adim never goes up. The counting block must always be outside the condition, before it.

### The ones that queue
The celebration melody lasts about 2.75 seconds. During this time the hat block is busy. New shakes that arrive join a queue, but at most 3 of them are kept, and any more are lost. This is why the counter can count too few with very fast events.

### Summary
The **when card is shaken** hat block counts one step on every shake. Exact equality is true once, and greater-than-or-equal is true on every step after it. The remainder operation sets up repeating goals. The counting block must be outside the condition. A busy hat block only queues 3 events.
