### A device is in one state at a time
Think of a door alarm. Either it is off (it does nothing), or it is set (it waits for a burglar), or it is ringing. It cannot be in two states at the same time. This way of thinking is called a **state machine**. For every state we ask: while I am in this state, which event takes me to which state?

| Current state | Event | New state |
|---|---|---|
| Off | A was pressed | Set |
| Set | the card was shaken | Ringing |
| Ringing | A+B was long-pressed | Off |
| Off | the card was shaken | Off (nothing happens) |

The last row is important: an event does not have an effect in every state. Shaking while the alarm is not set does not change anything.

### Keeping the state in two variables
Two variables are enough for three states. The kurulu ("set") and alarm variables are 0 or 1:

| State | kurulu | alarm |
|---|---|---|
| Off | 0 | 0 |
| Set | 1 | 0 |
| Ringing | 1 | 1 |

The shake hat block first checks "is kurulu = 1?"; if yes, it sets the alarm variable to 1. The hat block itself does not play the sound; it only changes the state. Playing the sound is a separate task.

### The task that checks all the time
The **forever** block is a loop that never ends. If you put "if alarm = 1, play the melody" inside it, the sound starts as soon as the alarm state becomes 1 and repeats until alarm becomes 0. The Alarm melody is 3.25 beats. At tempo 120 one beat is 500 ms, so the melody lasts about 1625 ms. If there is a 200 ms pause inside, one round is about 1825 ms, plus the small allowance that the system adds for each loop.

### Turning it off takes two jobs
The hat block that turns off the alarm must set alarm to 0. Just stopping the sound is not enough, because on the next round **forever** sees "alarm = 1" and rings again. The turn-off hat block resets the kurulu and alarm variables, stops the sound and gives the user a sign.

### Why is a long press a good password?
It is hard to press A+B for longer than a second by accident. Real alarms also ask for a difficult action like this so that they are not turned off by mistake.

### Summary
An alarm is a state machine: off, set, ringing. Variables keep the state, and events change the state. The check inside **forever** watches the state all the time. When turning it off, you need to reset both the sound and the state variable.
