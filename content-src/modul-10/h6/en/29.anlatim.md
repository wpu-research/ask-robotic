### A raw number is not a percentage
The analog value that comes from the pin is between 0 and 1023. We want to see "what percentage moist" the soil is. The operation that moves this number into the 0-100 range is called **mapping**. The logic is proportion: wherever you are in the input range, you go to the same place in the output range.

| P1 input | Proportion (input / 1023) | Percentage (rounded) |
|---|---|---|
| 0 | 0 | 0 |
| 256 | 0.25 | 25 |
| 512 | 0.5 | 50 |
| 1023 | 1 | 100 |

The **map** block rounds the result to the nearest whole number. For 512 it finds 50.05 and writes 50.

### Write the ranges in the right order
The block wants four numbers: input lowest, input highest, output lowest, output highest. Because the sensor gives 0-1023, the first two must be 0 and 1023, and because you want 0-100, the last two must be 0 and 100. If you mix up the order, the value 512 is moved from the 0-100 range to 0-1023, and a meaningless number such as 5238 comes out.

### Threshold and warning
When the moisture drops below 30, the plant is thirsty. The value 30 is called the **threshold**. The raw value that matches the threshold is about 307; but because of rounding, when 301 is read, 29 percent comes out and the warning starts, and at 302, 30 percent comes out and the warning stops. The threshold changes with each plant: 10 might suit a cactus better, and 40 a seedling.

### Bar graph and console
The **bar graph [value] up to [100]** block works out how many of the 25 LEDs light up: value / largest x 25, then it is rounded. If the moisture is 50 and the largest is 100, you get 12.5, and 13 LEDs light up. If you enter the wrong largest value, the graph stops making sense. The **print to console** block, on the other hand, keeps the values as a record; you can see them in the console even if the screen is cleared.

### Each sensor from its own slider
The temperature comes from the card's own sensor. The moisture comes from the virtual sensor connected to the P1 pin. You must not mix them up. On a real sensor, the 0-1023 range can come out differently depending on the sensor; that is why a real sensor is calibrated first.

### Summary
The raw sensor value is turned into a percentage with **map**. Writing the ranges in the right order is essential. The threshold is a warning limit. The **bar graph** shows the value with LEDs compared to the largest value, and **print to console** keeps a record.
