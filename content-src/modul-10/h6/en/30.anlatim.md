### Plan first
Instead of starting a big project with blocks, write the flow on paper. There are four jobs in this project:

| Hat block | When does it run? | What does it do? |
|---|---|---|
| on start | once | sets the radio group and the variables |
| every 2000 ms | every two seconds | measures the moisture and sends it by radio |
| button A | when A is pressed | shows its own moisture |
| on radio received | when a message arrives | shows the state of the other pot |

Every row of the plan is one hat block. Once you have made the plan, the rest of the job is putting the blocks in place.

### Sender and receiver
The two cards run the same program. Each card both sends and receives. A card does not receive its own message; only the other card's message comes to it. That is why you should not take a measurement on the receiving card. When a message arrives, use the **received [value]** block; that is the other pot's moisture. If the receiving card reads its own P1, it shows its own moisture, and the project does not reach its goal.

### The name must match
The sender sends with the name "nem", and the receiver looks for the name "nem". Capital and small letters make a difference; "Nem" and "nem" count as different. In projects that use more than one name, this check filters out the wrong messages.

### Timing
Messages arrive every 2 seconds. The Sad melody lasts 3 seconds. The hat block is busy while the melody plays; at most 3 of the messages that arrive wait in the queue. Knowing this helps you understand why some messages do not show up on the screen straight away.

If Card 1's moisture is 50 and the largest value is 100, the bar graph lights 13 LEDs. If the largest value had been left at 1023, you would get 50 / 1023 x 25 = 1.2, and only 1 LED would light; so the largest value is the number that sets the scale.

### Summary
A good project is a plan first. Each hat block does one job. On the radio, the receiving side uses the value that arrives, not its own sensor. Message names must match exactly. Long jobs such as a melody make the messages that arrive join a queue. The bar graph's largest value must fit the measuring range.
