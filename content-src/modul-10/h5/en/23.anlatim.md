### What you will learn in this lesson
- The ideas of **encryption**, **key**, plain message and encrypted message
- How to build a simple cipher with addition and subtraction
- How a key stored in a variable keeps the two sides in step
- Why this cipher is easily broken

### What you should know first
- Making a variable and changing its value (Lesson 7)
- Sending and receiving numbers by radio (Lesson 21)

### The information changes on the way
Everyone in the same group can receive a radio message. If you do not want others to understand the information, you scramble it before sending it. This is called **encryption**. You have three things:

- **Plain message:** the real information, for example the digit 3.
- **Key:** a secret number that both sides know, for example 7.
- **Encrypted message:** the number that travels on the way.

### Encrypting by adding
The simplest method is to add the key:

```
encrypted = plain + key        3 + 7 = 10
plain     = encrypted - key    10 - 7 = 3
```

The sending side sends 10. Someone listening on the way sees 10, but cannot know that the real digit is 3. Because the receiving side knows the key, it takes away 7 and gets back to 3. Addition and subtraction are the opposite of each other; that is why the operation can be undone.

### Why is the key in a variable?
If you write the key separately in both the sending and the receiving block, you might change one and forget the other. Instead, you write it once in a variable called **anahtar** ("key") (inside **on start**), and both operations use it. You change the value in one place; the two sides stay in step. Because the two cards run the same program, both cards have the same key too.

### Wrong key, wrong result
Even if someone who does not know the key receives 10 and does the same subtraction, they cannot find the right result. For example, if they have no key (the variable has stayed 0), they see 10 − 0 = 10. If they think the key is 5, they find 10 − 5 = 5. But the result is wrong, and there is no error message either. Forgetting to set the key in **on start** has the same effect.

### Is this cipher strong?
No. If the key is a small number, the listener can easily find it by trying 1, 2, 3 ... Real ciphers use very large keys and very complicated operations. The aim here is not security but seeing the basic idea: the information changes on the way, and whoever knows the right key turns it back into what it was. Also, sending the key by radio ruins the idea, because the listener catches the key too.

### Summary
In encryption, the plain message is scrambled with the key, and the encrypted message is sent. If you encrypted by adding, the receiving side decrypts by subtracting. If the key is kept in a variable, the two sides stay in step. A wrong or missing key quietly gives a wrong result. This cipher can be broken by trying small numbers.
