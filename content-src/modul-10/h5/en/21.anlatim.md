### What you will learn in this lesson
- How the cards talk by radio, and what the **group** number is for
- That the side that sends a message and the side that receives it are programmed separately
- When the "on radio received" hat block runs
- How to make a decision based on the number that arrives

### What you should know first
- Button hat blocks and the **if ... then ... else** block (Lesson 6 and Lesson 8)
- Showing an icon on the screen (Lesson 3)

### Think like a walkie-talkie
Two walkie-talkies only hear each other if they are tuned to the same channel. On the Micro Card's radio, the channel is called a **group**. The group is a number between 0 and 255, so there are 256 different groups. Cards in the same group receive each other's messages; cards in different groups do not hear them. If the program says nothing, the card is in group 1.

### Sender and receiver
There are two separate jobs in radio, and you write separate blocks for each:

```
on button A pressed:
    radio send number 1

on radio received:
    if received number = 1 then show heart
```

The send block runs whenever you want; the message goes to the other card in the group. The receive hat block, however, runs by itself when the message **arrives**, without you calling it. This is like the button hat block: there, the event is a key press; here, the event is a message arriving.

### The message does not arrive instantly
In the virtual portal there is no distance between the two cards, but just like real radios, the message spends a short time on its way: about 10 milliseconds. Your eye does not notice this. The important rule is this: **the sending card does not receive its own message.** Card 1 sends, Card 2 receives. If the two cards run the same program, Card 2 can send too, and Card 1 receives.

### Deciding with the number that arrives
You look at the number inside the message with the **received [number]** block. This block only makes sense inside the receive hat block, because "the last message that arrived" is right there at that moment. Then you build a classic condition: if the number is 1, a heart; if not, a happy face. Depending on which number the sender sent, the other card does a different job. In this way, a single number becomes a small **command**.

### Silent mistakes
When the radio goes wrong, usually no warning appears. The card cannot know who is listening; it sends the message and its job is done. So check three things: are the two cards in the same group, is the send block inside the right button, is the hat block on the receiving side filled in?

### Summary
Radio messages travel between cards in the same group; the group is a number from 0 to 255. The send block sends the message, and the **on radio received** hat block runs when a message arrives. The sender does not receive its own message, and the message arrives about 10 ms later. You decide with the **if** block based on the number that arrives. If a message is not getting through, look at the group numbers first.
