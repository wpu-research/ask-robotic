### What you will learn in this lesson
- How to set up a shared **table** (protocol) that turns numbers into icons
- How to tell three or more options apart with a chain of **if** blocks inside each other
- How to copy the message that arrives into a variable and use it in several places
- How many messages the receive hat block puts in a queue

### What you should know first
- Sending and receiving numbers by radio (Lesson 21 and Lesson 22)
- Variables (Lesson 7)
- Playing a melody (Lesson 18)

### Numbers are an agreement
The heart emoji you send on a phone is really a number; the other person's phone turns that number back into a heart. For this to work, both sides must know **the same table**. Our chat table:

| Number | Icon | Key that sends it |
|---|---|---|
| 1 | heart | A |
| 2 | happy face | B |
| 3 | sad face | A+B |

This table is called a **protocol** (a communication agreement). If you change the table on one side and not on the other, the messages are misunderstood.

### A chain of if blocks inside each other
To tell three options apart, the questions are asked in order:

```
if mesaj = 1 then
    show heart
else
    if mesaj = 2 then
        show happy face
    else
        show sad face
```

If the first condition is true, the remaining questions are not looked at at all. The second **if** must be inside the **else** branch of the first block; if you put it outside, it becomes a separate question and the order breaks. The last **else** branch means "everything else": here, all numbers other than 1 and 2 show a sad face.

### Putting the message into a variable
If you are going to compare the same number in several places, you first put it into a variable called **mesaj** ("message"). At the start of the program you say "set mesaj to the received number", and then you use **mesaj** in the conditions. That way you do not have to find the **received** block again and again. If you forget to fill in the variable, its value stays 0; neither 1 nor 2 matches, and the last branch always runs.

### Messages join a queue
The **play melody** block waits until the melody ends. Birdsong lasts 1.25 seconds. If a new message arrives during this time, the receive hat block is busy; the message joins a queue. For the same hat block, at most **3 messages** can wait in the queue, and any more are thrown away. This is why some messages get lost when you send messages quickly.

### Summary
The chat app is based on a table of numbers; both sides must use the same table. Three options are told apart with a chain of **if** blocks inside each other, and the second **if** is in the first one's **else** branch. If the message that arrives is put into a variable, it can be used in many places. While a long receiving job is running, at most 3 new messages wait in the queue.
