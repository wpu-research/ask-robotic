### What you will learn in this lesson
- How to turn a sensor that faces one direction into a scanning sonar with a servo
- How to build the loop: change the angle, wait, measure, record
- How to find the smallest value (the nearest object) with the right starting value
- How the sensor's beam cone limits the scan resolution

### What you should know first
The servo from lesson 21 (`attach`, `write`, pulse width); the `pulseIn` measurement from lesson 37; the median filter from lesson 38; the `for` loop from lesson 4; functions from lesson 19.

### The idea: turning the sensor
The HC-SR04 only measures the direction it is facing. If you fix the sensor to the servo's arm, the sensor faces a different direction as the servo angle changes. If you take a measurement at each angle, you get a cross-section of the room. This is the logic of a submarine's sonar.

### The scan loop
For each angle, the same four steps are repeated:

```
for (int aci = 0; aci <= 180; aci += 30) {
  servo.write(aci);        // 1. go to the angle
  delay(300);              // 2. let the servo get there
  float cm = olc();        // 3. measure
  // 4. print as aci:cm, update the smallest
}
```

The waiting step is a must: if you measure while the servo is still turning, it gets unclear which angle the measurement belongs to. With a 30° step there are 7 measuring points: 0, 30, ... 180.

### Finding the smallest value
To find the nearest object, you keep "the smallest so far". The starting value must be **large**:

```
float enYakin = 400.0;     // the largest in range
int enYakinAci = -1;       // -1: not found yet
if (cm < enYakin) { enYakin = cm; enYakinAci = aci; }
```

If you made the start 0, no measurement could be smaller than 0 and you would never find the object. If `enYakinAci` is still -1 when the scan ends, there is no object.

### Writing the data neatly
Printing each measurement in the form `aci:mesafe` (for example `120:35.0`) is a good habit. A spreadsheet program or PC code can read the data by splitting at the `:` sign.

### The beam is like a cone
The HC-SR04 looks at a cone, not a single line; the datasheet typically gives a measuring angle of about 15°. 30° steps can leave gaps in some directions that the cone does not cover, and a thin object can fall between two steps and be missed. If you make the step smaller, the resolution goes up but the scan takes longer: if each step takes about 400 ms, 7 steps take about 2.8 s and 19 steps (10°) about 7.6 s.

### Summary
A servo and an ultrasonic sensor scan together: set the angle, wait for the servo, measure, record. The nearest object is found with "keep the smallest" logic that starts from a large value. As the step gets smaller, the resolution goes up but the scan takes longer; because of the beam cone, very small objects can be missed.
