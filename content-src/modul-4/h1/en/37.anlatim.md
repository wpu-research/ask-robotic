### What you will learn in this lesson
- How to give the right trigger pulse on the TRIG pin
- How to measure how long a pin stays HIGH with `pulseIn()`
- Why a timeout is needed, and how to interpret a return value of `0`
- How to put the measurement in a function and tell an invalid measurement apart

### What you should know first
The distance formula from lesson 36 (time × 0.0343 / 2); `pinMode` from lesson 3, `digitalRead` from lesson 6; functions from lesson 19; `millis()` from lesson 27.

### A measurement in three steps
1. **Trigger.** Hold TRIG LOW for 2 µs, make it HIGH for 10 µs, then pull it LOW again. For waiting in microseconds you use `delayMicroseconds()`; `delay()` works in milliseconds and is far too slow here.
2. **Measure the time.** You read how long ECHO stays HIGH, in microseconds.
3. **Convert.** You turn the time into centimetres (lesson 36).

```
digitalWrite(TRIG, LOW);
delayMicroseconds(2);
digitalWrite(TRIG, HIGH);
delayMicroseconds(10);
digitalWrite(TRIG, LOW);
unsigned long sure = pulseIn(ECHO, HIGH, 30000);
```

### How does pulseIn work?
`pulseIn(pin, HIGH, zamanAsimi)` waits for the pin to go HIGH, then returns the time that passes until it goes LOW again, in microseconds. The third parameter is the **timeout** (µs). If the pulse does not finish within this time, the function returns `0`. If you do not write a timeout, the default is 1 second: with no echo, the program hangs for a second.

Choosing 30 000 µs matches about 514 cm (30 000 × 0.0343 / 2); it covers the sensor's 400 cm limit.

### Zero is not a distance
If `pulseIn` returned 0, no echo came back. If you put this into the formula you get "0 cm", and the program behaves as if the object were sitting on the sensor. That is why `sure == 0` is checked first:

```
if (sure == 0) return -1;            // invalid measurement
return sure * 0.0343 / 2.0;
```

After that, a condition such as `cm >= 0 && cm < 30` does not count an invalid measurement as "close".

### Type and pause
`pulseIn` returns an `unsigned long`; keep the variable in this type too. A pause is left between measurements; datasheets usually suggest about 60 ms, so the echo of the previous measurement does not get mixed into the new one.

### The cost of blocking
`pulseIn` makes the program wait until the measurement finishes. At 100 cm this is about 6 ms; with no echo, it is the full timeout: 30 ms. If you have other jobs, such as watching a button, a screen or a buzzer, measure less often and time it with `millis()` (lesson 27).

### Summary
For a measurement, a 10 µs pulse is given on TRIG, and `pulseIn` returns the ECHO time in microseconds. The timeout stops the program hanging; if it returns 0, there is no echo and it must not be used as a distance. Measuring is blocking, so how often you measure is chosen with care.
