### What you will learn in this lesson
- Why a distance sensor sometimes reads wrongly
- What an outlier is
- The difference between the average and the **median**, and why the median is robust
- How to keep the last N readings in a sliding window, and the delay cost of the filter

### Where does a wrong reading come from?
Sound bounces back; the result depends on the surface. A flat wall facing the sensor sends the sound back to it. A slanted surface sends the sound off to the side: either the echo never arrives, or it goes round via another surface and arrives late. Fabric and sponge swallow the sound. Very thin objects (a cable, a chair leg) reflect very little. If a motor powered from the same line makes the voltage drop, the measurement can go wrong too. In the end, a sensor that measures correctly most of the time now and then gives a value very different from its neighbours: an **outlier**.

### Average or median?
The **average** adds up all the values and divides by how many there are. The **median** sorts the values and picks the one in the middle. Five readings: 100, 100, 100, 350, 100.

```
average = (100+100+100+350+100) / 5 = 150
median  : 100,100,100,100,350  ->  middle = 100
```

A single wrong value spoilt the average by 50 cm and did not affect the median at all, because the outlier goes to the end of the sorted list and is not chosen. The rule: in a window of N elements, the median forgives at most (N − 1) / 2 outliers. A window of five stands up to 2 wrong values, a window of seven to 3. If the wrong values are more than half, the median is fooled too.

### The sliding window
The readings keep flowing past, and you store the last N of them. When a new reading arrives, it is written in place of the oldest one:

```
pencere[sira] = yeniOkuma;
sira = (sira + 1) % N;      // 0,1,2,3,4,0,1,...
```

`% N` stops the index running off the end of the array. The window must be filled with the first reading at the start of the program; otherwise the zeros at the start spoil the median. When you take the median, you first **copy** the array and sort the copy; the real window's order keeps showing which value is the oldest.

### The cost: delay
If the distance really drops from 100 cm to 50 cm, a five-element median stays at the old value until 3 new values have built up in the window. If a measurement is taken every 55 ms, that means about 165 ms. The bigger the window, the more robust it is, but the slower it reacts. The window size is chosen **odd**; if it is even, the middle is unclear.

### Summary
Sensors produce an outlier now and then. The average takes it in, while the median throws it away. With a sliding window and `% N`, the last N readings are kept; the median forgives at most (N − 1) / 2 wrong values. The price is reacting late to a real change.
