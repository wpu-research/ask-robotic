### What does a sound sensor measure?
A sound module has a microphone and an amplifier. When the room is quiet, the analog output (AO) sits at a steady **baseline level**. When a sound arrives, the output swings both above and below this level. The baseline differs from module to module: our virtual module reads about 256 when quiet, not 512. So instead of assuming the baseline, you **measure** it.

```
int baz = average(64 readings);        // when quiet, at start-up
int fark = abs(analogRead(A0) - baz);  // deviation
```

`abs()` ignores the direction of the deviation: a swing above the baseline and one below it are deviations of the same size. At a Sound level of 0.5 the virtual module reads about 614; since the baseline is 256, the deviation comes out as 358.

### Height alone is not enough
When the deviation goes above a threshold (for example 150), an **event** starts. But a door slam, shouting and music also go above this threshold. What sets a clap apart is its **duration**:

```
Duration < 10 ms     -> short interference
10 ms - 500 ms       -> clap
Duration > 500 ms    -> long sound (music, shouting)
```

The duration is the difference between the start of the event and the **last loud sample**. For this you save a `baslangic` (start) when the event begins and a `sonYuksek` (last loud) on every loud sample.

### The quiet margin
A real microphone signal swings; while it swings it sometimes passes through the baseline and the deviation briefly gets close to zero. If you end the event at once, one clap looks like two events. So you end the event when the deviation has stayed below the threshold for `SESSIZ_PAY` (20 ms).

### Non-blocking code that keeps a state
The `olayOku()` function is called on every pass of `loop()`. On most passes it returns `0` straight away. Because it has a state variable called `sesVar`, it remembers whether it is in the middle of an event. Since `delay()` is not used, the program keeps measuring all the time.

### Toggle with two claps
The clap switch looks at the time between the **starts** of two claps. If the gap is shorter than `ARALIK`, the LED's state is flipped. A single clap is only remembered as the "first clap". If the second clap comes late, it counts as a new first clap. If a long sound comes in between, the memory is wiped.

### Summary
A sound sensor swings around a baseline; you measure the baseline and work out the deviation with `abs`. To recognise a clap, you look at both the height and the duration of the deviation. The quiet margin stops the swinging signal from splitting one event into pieces. Non-blocking code with a state variable runs the two-clap logic without `delay`.
