### What does a flame sensor read?
A flame sensor is sensitive to the **infrared (IR) light** that a flame gives off. On many modules the analog value **drops** when a flame comes close; on some it rises. The virtual module drops: AO = 5 V × (1 - 0.95 × intensity). Sunlight and some lamps also give off IR, so in a real circuit false alarms can happen.

### Sort out the direction in one place
Instead of thinking about the direction in every comparison, you turn the raw reading into an **intensity** number: a big number means a strong flame.

```
int siddet(int ham) {
  return ALEVDE_DUSER ? 1023 - ham : ham;
}
```

For example, if the raw reading is 700, the intensity is 323. If the module works the other way round, only `ALEVDE_DUSER` changes.

### Three levels, four thresholds
Every transition between levels has its own threshold:

```
NORMAL  -> UYARI    : deger >= uyariAc
UYARI   -> NORMAL   : deger <  uyariKapat   (smaller than uyariAc)
UYARI   -> TEHLIKE  : deger >= tehlikeAc
TEHLIKE -> UYARI    : deger <  tehlikeKapat (smaller than tehlikeAc)
```

That way the hysteresis from lesson 51 works in two places. Example: if the thresholds are 300/250/600/500, a system that has entered `UYARI` stays in `UYARI` at an intensity of 280; when it drops to 240 it becomes `NORMAL`.

You do not name the levels with numbers like `0, 1, 2` but with `enum Seviye { NORMAL, UYARI, TEHLIKE }`. Because the values are 0, 1, 2, comparisons like `UYARI < TEHLIKE` also work.

### The decision depends on the current level
The `seviyeBul(simdiki, deger, ...)` function takes both the current level and the reading, and returns the **new level**. It can go from `NORMAL` straight to `TEHLIKE` (if a flame appears suddenly) or from `TEHLIKE` straight down to `NORMAL`.

### Put an end to repeated code
If you copy the same `if` chain twice for flame and gas, you have to fix a bug in two places. The fix: call the same function **with different thresholds**. For the flame, fixed thresholds are used; for the gas, multiples of the baseline (1.5; 1.25; 2.5; 2).

To find the overall state from the two sensors' levels, you take the worst one:

```
Seviye enKotu(Seviye a, Seviye b) { return (a > b) ? a : b; }
```

If one of the sensors is `TEHLIKE`, the system is `TEHLIKE`.

### Summary
The flame sensor's direction is sorted out in a single function. Three levels need four thresholds, and the decision depends on the current level. An `enum` makes the levels readable. The `seviyeBul` function with parameters lets you use the same logic for several sensors; the overall state is the worst of the sensor levels.
