### Lasting memory
A PIN written inside the code needs the program to be uploaded again to change it. Information in RAM is lost when the power goes off. **EEPROM**, however, keeps the information it holds even if the power is cut. If the authorised cards and the PINs live here, the manager can change them with a command, and the list is still there when the device starts up again.

### The EEPROM map
If you do not give each piece of information a fixed address, you write one on top of another. In this lesson:

| Address | Size | Contents |
|---|---|---|
| 0 | 1 byte | Setup marker (0xA5) |
| 1-4 | 4 bytes | User PIN |
| 5-8 | 4 bytes | Master PIN |
| 9 | 1 byte | Number of cards |
| 10-41 | 8 × 4 bytes | Card UIDs |

The address of the first byte of card `k` (counting from 0) is `10 + k * 4`. At most 8 cards fit, because 8 × 4 = 32 bytes are set aside.

### The setup marker
In a new EEPROM every cell holds 255; the program must not mistake this for a PIN. At start-up, if `0xA5` is not at address 0, the device is running for the first time and the factory settings are written. We write the marker **last**: if setup is interrupted half-way, the marker is missing and setup is done again from the start at the next start-up.

### The order of writing and wear
When adding a card, you write the card's bytes first and the card counter **last**. If the power goes in the middle, the counter has not gone up and the half-written card does not appear in the list. Each cell is guaranteed for about 100,000 writes. `EEPROM.update` does not write if the value is the same; reading and checking use up no writes at all. When deleting a card, instead of rewriting the list from the start, you **copy the last card into the deleted one's place** and reduce the counter by one; the list stays without gaps and at most one card's worth of writing is done.

### The master PIN
Adding and deleting cards and changing the PIN are management jobs; they cannot be done with the ordinary user PIN. All these commands check the **master PIN** first. If the two are the same, management is open to everyone. Commands such as `EKLE:9999:AABBCCDD` are split into fields with `:`; when you put a `'\0'` in place of each `:`, each field becomes a text of its own.

### Summary
EEPROM keeps the access information even when the power is cut. A map that gives every piece of information a fixed address is needed, and a setup marker tells the first start-up apart. When writing, the counter is updated last, so a half record does not show. On deletion, the last card is moved into the empty place. The management commands are protected with a master PIN.
