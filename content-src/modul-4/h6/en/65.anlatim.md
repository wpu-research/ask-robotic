### Rule first, code second
The smart door lock's rule is short: the right PIN or an authorised card opens the door for 5 seconds; after three wrong attempts, the door accepts no input for 30 seconds. When you write this, the first job is to work out the states:

| State | Servo | Exit |
|---|---|---|
| KILITLI (locked) | 0° | Right input: ACIK. 3rd wrong one: BLOKE |
| ACIK (open) | 90° | When 5 s are up, KILITLI |
| BLOKE (blocked) | 0° | When 30 s are up, KILITLI |

Before you write the code, the table shows where you can go from each state; the code is a translation of this table.

### One variable, many jobs
A single variable called `durum` (state) tells you where the door is. On every pass, `loop()` does five jobs: it reads the keys, handles the serial line, checks the times, updates the LEDs and updates the screen. None of them has a `delay`; that is why, even while the door is open or blocked, the program **listens** to the inputs (and ignores them if the state does not allow them).

### Telling when the time is up
The end moment is worked out with `millis() + süre` (duration), and the check is done with `(long)(simdi - bitis) >= 0`. This subtraction gives the right result even when `millis()` goes back to zero and overflows after 49 days.

### A shared attempt counter
The PIN and the card use the same `yanlis` (wrong) counter. Two wrong PINs and one unauthorised card make three attempts in total. If the counters were separate, an attacker would make three attempts separately through each way. A correct entry resets the counter.

### Servo and power
The servo takes commands from its signal pin (D10); it draws its power from 5V and GND. In the lab it is enough to connect VCC and GND. In a real circuit, even a small servo draws a brief high current when it starts; a separate 5 V supply is used, and the supply's GND is joined to the Arduino's GND. For a servo at 90°, the library produces a pulse of about 1472 µs.

### Summary
Write the rule and the state table first, then move on to the code. A single `durum` variable, checking times with `millis()` and not using `delay` keep the lock responsive all the time. The PIN and the card share one error counter. In a real circuit the servo is powered separately and the GNDs are joined.
