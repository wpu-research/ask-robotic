### Why a matrix?
If each of the 16 keys needed its own pin, the Uno would run out of pins. The solution is to arrange the keys as a **matrix**: 4 rows and 4 columns. When a key is pressed, it joins one row to one column. The number of pins is rows plus columns: 4 + 4 = 8. The bigger the matrix, the bigger the saving; in a 4x4 matrix, 16 keys are read with 8 pins.

### How scanning works
The row pins wait at HIGH with `INPUT_PULLUP`. The board makes the columns LOW in turn, only one at a time:

```
column 1 LOW  -> look at the rows
column 2 LOW  -> look at the rows
...
```

While the column of a pressed key is LOW, that key's row also reads LOW. Whichever row reads LOW while whichever column is LOW, the key is where the two cross. You repeat this scan very fast; debouncing is the library's job too.

### getKey and characters
On a new press, `getKey()` returns the key as a `char`; if there is no press, it returns `'\0'`. Even if you hold the key down, it gives it once. That is why writing `if (tus)` means "has a key just been pressed?".

### Collecting the PIN
When digits arrive, they are added to a `char` array; after each addition a `'\0'` is put at the end, because in C a piece of text ends with `'\0'`:

```
sütun 1 LOW  -> satırlara bak
sütun 2 LOW  -> satırlara bak
...
```

The array must be **one bigger** than the PIN length (5 for 4 digits). With `*`, `hane` is reduced by one and `'\0'` is written in that place; that way the last digit is deleted.

### Comparing and timing
You must not compare two texts with `==`. `==` compares memory addresses, not the contents, and nearly always comes out false. Compare the contents with `strcmp(a, b) == 0`. Manage the wrong-entry counter and the time the LED stays lit with `millis()`; if you use `delay`, keys pressed during that time can be missed.

### Summary
A matrix is the way to read 16 keys with 8 pins: a column is set LOW, and the row that reads LOW gives the key away. `getKey()` returns a character once per press. The PIN is collected in an array ending with `'\0'` and compared with `strcmp`. Using `millis()` instead of a blocking `delay` stops keys from being missed.
