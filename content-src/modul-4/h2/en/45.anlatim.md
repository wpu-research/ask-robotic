### States first, then code
Four states are enough:

| State | Meaning | Buzzer |
|---|---|---|
| `DEVRE_DISI` (disarmed) | The sensors are ignored | Silent |
| `HAZIR` (armed) | Armed, waiting for a breach | Silent |
| `ALARM` | A breach has happened | Siren |
| `SUSTURULDU` (silenced) | The alarm has been silenced, the event is remembered | Silent |

Transitions: pressing the button starts the arming process from `DEVRE_DISI`; when the 5-second exit delay ends, the state becomes `HAZIR`. In `HAZIR`, if the PIR goes HIGH or the door opens, `ALARM` starts. The code or the time running out moves `ALARM` to `SUSTURULDU`.

### The exit delay
If the alarm went off straight after arming, you could not leave the house. That is why, after you press the arm button, the sensors are not listened to for 5 seconds. If the door is still open when the time is up, arming is cancelled. The PIR's hold time matters here too: if you untick the motion box 3 seconds after the button, OUT stays HIGH for another 3 seconds, that is, until second 6; the alarm goes off as soon as the system becomes `HAZIR` at second 5.

### The latch and the silenced state
`ALARM` behaves like a **latch**: even if the PIR goes back to LOW and the door closes, the alarm continues until the code is entered or 10 seconds have passed. When the time is up, it moves to `SUSTURULDU`, not `DEVRE_DISI`; this way the sound stops, but the slowly blinking LED reminds you that the event happened. In `SUSTURULDU` the sensors are not checked, so new motion does not set the alarm off again.

### The code window
The code: three presses within 3 seconds. The window is counted **from the first press**. If the presses come at t = 0, 1500, 3200, 3500, 4000 ms, the press at 3200 falls outside the window, so the counter starts again from 1; three presses are only completed at 4000. This is how the code stops the alarm from being switched off by a single accidental press.

### The non-blocking loop
There is no `delay()` anywhere in the program. On every pass, `loop()` checks the button, the sensors and the timers; the LED patterns are produced with expressions such as `simdi % 500 < 250`. If `delay(5000)` had been written, the button and the door could not be checked during the exit delay.

### Summary
An alarm is a table of four states and the transitions between them; the code writes this table with `enum` and `switch`. The exit delay, the latch and the code window protect the user while keeping the system reliable. All of them are measured with `millis()`; there is no `delay()` anywhere.
