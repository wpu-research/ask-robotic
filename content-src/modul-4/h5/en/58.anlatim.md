### The chip measures gravity
A still accelerometer measures one thing: the gravity vector, about 1 g in size. When the chip is flat, this vector is on the Z axis (`az` = 1, `ax` = `ay` = 0). When you tilt the chip, the vector is shared between the axes. To find the angle, you read how it is shared.

### Registers: the chip's numbered cells
Inside the MPU6050 there are numbered cells called registers:

| Register | Job |
|---|---|
| 0x6B | Power management. The chip starts up asleep; if you write 0, it wakes up. |
| 14 bytes from 0x3B | Accel X, Y, Z, temperature, gyro X, Y, Z (2 bytes each) |

The chip is at address 0x68 (0x69 if AD0 is connected to 5V). The RTC module also uses 0x68, so they cannot be used on the same line.

### Turning bytes into a number
Each measurement is 16-bit signed, and the high byte comes first:

```
int16_t ham = (int16_t)((yuksek << 8) | dusuk);
float g = ham / 16384.0;
```

In the default ±2 g range, 1 g = 16384 raw units. Raw 8192 is 0.5 g. You need to write `16384.0` instead of `16384`; dividing two whole numbers gives a whole number, and a result smaller than 1 becomes 0. `int16_t` reads a negative tilt correctly; an unsigned `int` turns a negative value into a number like 65000.

### Tilt angle
Imagine a triangle whose horizontal side is `az` and whose vertical side is `ax`. The angle is the arctangent:

```
pitch = atan2(ax, az) * 180.0 / PI;
```

`atan2` gives radians; multiplying by 180/π gives degrees. Example: if `ax` = 0.5 and `az` = 0.866, pitch is 30 degrees. For roll, `atan2(ay, az)` is used.

### Know the limit
The accelerometer cannot tell gravity apart from the chip's own acceleration. If `ax` = 0.3 g without the chip tilting, `atan2(0.3, 1)` gives about 16.7 degrees, yet the chip is not tilted. That is why measuring an angle with an accelerometer alone is misleading on a moving device.

### Summary
The raw value read from the MPU6050's registers becomes g when divided by 16384. If the chip is still, the tilt angle is found with `atan2` from how gravity is shared between the axes. You need to wake the chip by writing 0 to `0x6B`, join the bytes with `int16_t` and divide with decimals. Acceleration spoils the angle calculation.
