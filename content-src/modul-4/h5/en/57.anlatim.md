### What you will learn in this lesson
- Why the rotary encoder's two signals (CLK and DT) are shifted by 90 degrees
- How to find the direction of rotation with the rule "look at DT when CLK falls"
- How to count the encoder with `attachInterrupt` and a `volatile` variable
- How to filter out contact bounce with a time threshold

### What you should know first
Lesson 6: `INPUT_PULLUP`; lesson 8: button bounce and edge detection; lesson 29: `attachInterrupt`, the ISR and `volatile`.

### One tick, two signals
There are two contacts inside the encoder. As the knob turns, these contacts do not change at the same time; one changes before the other. If we write the pins in order (CLK, DT), one tick goes through these states:

```
Clockwise : 11 -> 01 -> 00 -> 10 -> 11
Opposite  : 11 -> 10 -> 00 -> 01 -> 11
```

Four state changes make one tick. A potentiometer has a start and an end; an encoder turns forever and knows its position only by counting.

### The rule that finds the direction
Look at the two orders: CLK falls from 1 to 0 in both directions, so CLK alone does not tell you the direction. The difference is in DT at that moment. Clockwise, when CLK falls, DT is still 1 (11 -> 01). In the opposite direction, DT has already become 0 (10 -> 00). The rule:

```
When CLK falls: if DT = 1 then sayac++, if DT = 0 then sayac--
```

Which direction the module counts as positive may vary from maker to maker; if it is reversed, swap `++` and `--`.

### Counting with an interrupt
When you turn fast, constantly checking inside `loop()` can miss ticks. You connect CLK to an interrupt pin (D2 or D3 on the Uno) and write a short ISR that runs on the `FALLING` edge. The ISR only reads DT and changes the counter. `Serial.print` and `delay` are not used in the ISR. Because `sayac` is used both in the ISR and in `loop()`, it must be `volatile`; while `loop()` reads it, the interrupt is switched off for a short moment.

### Bounce and the threshold
Real contacts open and close for a very short time as they close. The interrupt counts each edge separately; one tick can skip 3 counts. The fix is to ignore an edge if at least a certain time has not passed since the previous one (with `micros()`, for example 2000 µs). If the threshold is too large, real ticks are thrown away too. The lab's encoder applies one state change every millisecond: 4 ms per tick, so at most 250 ticks/s. The threshold must be smaller than these 4 ms.

### Summary
An encoder gives both the step and the direction with two signals shifted by 90 degrees. When CLK falls, if DT is 1 you are going one way, if it is 0 the other way. Counting is done with an interrupt, and the shared variable is `volatile`. A time threshold is added to filter out bounce, but the threshold must stay smaller than the fastest gap between ticks.
