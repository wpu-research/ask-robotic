### Ping, but no data
A gimbal camera was connected to a laptop over USB-Ethernet. `ping` was answering, but the telemetry and the video kept dropping. In this case from the Hyvex team's internship programme, the root cause was not the software: NetworkManager was deleting the device's IP with DHCP, and the fix was to set up a permanent static profile. The clue in the case is the sentence "it sorts itself out now and then": one layer is unstable.

The lesson is this: just because **one** layer of something works does not mean all of them work.

### Four layers
On an I2C sensor, the "ping" is the address scan. We look for the fault from the bottom up, and the first layer that fails is the root cause:

| Layer | Question | How to try it |
|---|---|---|
| 1. Physical | Are the SDA/SCL lines HIGH when idle? | `digitalRead(A4)`, `digitalRead(A5)` |
| 2. Address | Does the expected address answer? | `beginTransmission` / `endTransmission` |
| 3. Identity | Is the one answering the right device? | Read the WHO_AM_I register (0x75 on the MPU6050, expected 0x68) |
| 4. Data | Is the value sensible? | Range check (acceleration at rest ≈ 1 g) |

An answer at the address does not prove the identity: another device can use the same address. Even if the identity is right, a frozen sensor can always give 0. That is why each layer is tested separately.

### The limit of the sensibility check
The size of the vector of a resting accelerometer's three axes is about 1 g:

```
g = square-root(x*x + y*y + z*z)
```

If you chose a range of 0.8-1.2 g and the sensor is tilted or moving, the total size can go outside this range (for example g ≈ 1.22 for x = 0.5, y = 0.5, z = 1). This is not a sensor fault; the condition under which the check is valid (at rest) has not been met.

### Checksum
If a message travels a long way, it can get corrupted. To tell this, the receiver uses a **checksum**. A simple method is the **XOR** of certain bytes. Our frame: sync (0xAA), length N, N data bytes, last byte = the XOR of N and the data bytes. The receiver recalculates the XOR itself; if it does not match, it ignores the frame.

Example: `AA 02 01 01 02`. N = 2, data 01 and 01. 2 XOR 1 XOR 1 = 2, which matches the last byte 2: the frame is valid.

### Summary
One layer answering does not show that the system works; look for the fault in the physical, address, identity and data layers from the bottom up. The identity register gives much more information than a ping. A sensibility range only means something under the condition in which it is valid. A checksum stops you taking a corrupted message for a valid one. The sentence "it sorts itself out now and then" is a sign that a layer is unstable.
