### What is the project?
This project is a **weather station** and a **watering alert**. The system measures the temperature, humidity, pressure, altitude and soil moisture, and shows them page by page on the LCD. When the soil dries out, the LED lights up, the buzzer starts beeping and a line is written to the serial port. There is no pump; a real pump needs a transistor or a relay and a separate power supply.

### Plan first: states and rules
Putting the behaviour into a table before you write the code makes the job easier:

| State | When | Action |
|---|---|---|
| Normal | soil moisture 30 % or above | LED off, buzzer silent |
| Normal → Alert | moisture drops below 30 % | LED on, buzzer beeps, one line is written |
| Alert | moisture between 30 % and 40 % | the alert continues |
| Alert → Normal | moisture rises to 40 % or above | LED off, buzzer silent, one line is written |

The `uyari` (alert) variable in the project holds this state. The changes only happen when a threshold is crossed.

### Why two thresholds?
If you used a single threshold (for example 30 %), the alert would keep switching on and off when the moisture wobbled between 29 and 31. Between two thresholds (lower: 30, upper: 40), the state is kept. This is called **hysteresis**. A thermostat works the same way.

### Four jobs, no delay at all
Inside `loop()`, four jobs run on their own clocks: the button (straight away), the measurement (2 seconds), the page (3 seconds) and the buzzer (a short beep every 2 seconds during the alert). For the buzzer, `tone(pin, frekans, süre)` (pin, frequency, duration) is used; this command does not wait, and the sound plays in the background. A `delay` would stop all the other jobs.

### Write the message only when the state changes
The alert message is written to the serial port only once, **not on every round but only when the state changes**; this way the Serial monitor does not fill up with the same line. Writing `sonBip = simdi - BIP_ARALIGI` when the alert switches on makes the first beep play straight away.

### If a sensor breaks
A broken DHT produces `NaN`, and a BMP280 that is not found produces `bmpHazir = false`; the screen writes `--` and `BMP280 yok` (no BMP280), and the program carries on. But what if the soil sensor always reads "dry" or always reads "wet"? You get an endless alert or no alert at all. In reliable systems, the health of the sensor is checked separately.

### Summary
The project combines pieces from the earlier lessons: the DHT, the BMP280, soil moisture, LCD pages, an LED and a buzzer. First you put the states and the changes between them into a table. Two thresholds stop the alert from flickering. Each job runs with its own timer without `delay`, and a sensor fault does not crash the program.
