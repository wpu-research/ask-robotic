### Two measurements in one sensor
The **DHT** family (DHT11 and DHT22) measures both temperature and **relative humidity**. Relative humidity tells you what percentage of the most water vapour the air can hold at that temperature it is holding: 0 % means very dry air, 100 % means saturated air. The sensor sends both values as digital packets over **a single data line** (DATA). Decoding this packet by hand is hard, so we use the `DHT.h` library. You only tell it the pin and the model.

```
DHT dht(5, DHT22);        // pin D5, model DHT22
float nem = dht.readHumidity();
float sic = dht.readTemperature();
```

### Choosing a model
Both models are read with the same library; the difference is in resolution and detail. In the lab the DHT22 gives the temperature with one decimal place (23.5), while the DHT11 gives it as a whole number (24). But seeing more digits on the screen does not mean **more accurate**. Accuracy is how close the sensor gets to the real value, and you find it in the datasheet. The model in the code must match the sensor; with the wrong model the values make no sense.

### A reading can fail
If a wire is loose or the sensor does not answer, the library returns **NaN** ("not a number"). Every calculation with NaN gives NaN again, and the screen shows `nan`. The fix is to ask before you use the value:

```
if (isnan(nem) || isnan(sic)) {
  Serial.println("Okuma hatasi");
  return;
}
```

`||` means "or": if either of the two values is broken, the reading is thrown away.

### A slow sensor
The DHT is not a fast sensor. You must wait **at least 2 seconds** between two readings. If you ask more often, you usually get the same old value. `delay(2000)` is the simple fix; if you count the 2-second interval with `millis()`, the program can do other jobs without waiting.

### What if there is no sensor?
A good program keeps working even with a broken sensor. The version at the end of the lesson has a **consecutive error counter**: it goes up with every failed reading and goes back to zero with a successful one. When the counter reaches 3, the program stops showing the old value and says `SENSOR YOK` (no sensor). Showing an old temperature for hours as if it were up to date would be misleading.

### Summary
The DHT sensor gives temperature and relative humidity over a single data line. If the library cannot read it, it returns `NaN`, so the value is checked with `isnan` before it is used. You wait at least 2 seconds between readings. A consecutive error counter lets the program report the problem without crashing when the sensor is disconnected.
