### What does the project do?
The device takes a measurement every 10 seconds, produces a timestamped CSV row (writes it to Serial, and to the card as well in the SD version) and shows the latest measurement on the LCD. A button (D2) stops and restarts logging. First put the plan into a table:

| Task | Part | How |
|---|---|---|
| Time | RTC (I2C, 0x68) | `rtc.now()` |
| Measurement | DHT22 (D5) | `readTemperature()`, `readHumidity()` |
| Display | I2C LCD (0x27) | Measurement on top, time and state underneath |
| Control | Button (D2, `INPUT_PULLUP`) | Turns logging on/off when pressed |
| Logging | Serial (SD in the SD version) | `satirOlustur()` |

The RTC and the LCD share the same two wires (A4, A5); because their addresses are different, they do not get mixed up.

### The RTC decides the time
If you use `delay(10000)`, the button and the screen freeze during that time. Counting 10 seconds with `millis()` is better, but it can drift over time. In this project, a row is produced when the RTC's `unixtime()` value (the seconds since 1970) divides exactly by 10. That way the rows come out in exact steps such as 08:30:10, 08:30:20. The RTC is read every 200 ms; this is often enough not to miss a single second. Because the condition stays true on each 200 ms pass, the `u != sonKayit` flag is needed. Without it, five rows are written in the same second.

### Do not stop when there is an error
When the DHT reading fails, `NaN` comes back. You still write the row: the timestamp stays and the sensor fields are empty. `--` appears on the screen. In the SD version, if there is no card or writing fails, the device writes the warning to Serial and keeps running. Even when a logger cannot take a measurement, it should record the fact "I could not take a measurement".

### Architecture: only `kaydet()` changes
The only difference between the Serial version and the SD version is the `kaydet()` (save) function. The row format never changes. The SD library increases RAM use a lot; the Uno has 2048 bytes of SRAM in total, so you should look at the RAM use in the compile output.

### Summary
The data logger combines the RTC time, the DHT22 measurement, the CSV row and button control. The logging time is linked to the RTC's seconds, and a flag stops repeat writes in the same second. A reading error does not stop logging; the field is written empty. Only `kaydet()` decides where the row goes.
