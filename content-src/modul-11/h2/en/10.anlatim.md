### What you will learn in this lesson
- How to design a complete game as a **goal, a risk and an ending**
- How to split the game into independent events
- How to use the **countdown** and the `when time runs out` event
- How to write the winning and losing rules without them clashing

### What you should know first
Collisions from lesson 6, the score and `if score ≥ ...` from lesson 7, every ... ms and randomly falling objects from lesson 8, lives and `when lives run out` from lesson 9. This lesson brings these pieces together more than it adds a new idea.

### The three parts of a good game
| Part | In the fruit hunt |
|---|---|
| Goal | Collecting 8 fruits |
| Risk | Bombs (5 lives) and time (45 seconds) |
| Ending | Winning or losing |

If one of the three is missing, the game is boring. Without a goal, you do not know what to do. Without a risk, there is no excitement. Without an ending, the game never finishes.

### Splitting into events
A big job is split into small events that each do one job:

| Event | Its job |
|---|---|
| `when game starts` | Set up the stage, make the score 0 and the lives 5, start the countdown from 45 seconds |
| `every ... ms` (two of them) | Drop fruit; drop bombs |
| when a Player hits a Food | Raise the score, do the winning check |
| when a Player hits an Enemy | Lower the lives, shake, delete |
| `when lives run out` | You lose |
| `when time runs out` | You lose |

If something breaks, you only look at the event involved.

### Countdown
The `start countdown from [45] seconds` block starts the time, and the time left is shown on the screen. When the time reaches 0, the `when time runs out` event runs. If you do not write this event, the game says "TIME IS UP" by itself; if you write it, ending the game is up to you. To run the block you must put it inside an event; `when game starts` is the best choice.

### The one-ending rule
Think about whether the winning and losing blocks could run at the same time: you get the 8th fruit and the time runs out in the same frame. The game applies the first `end game` block; the later ones are ignored. So set up the rules clearly, in a way that they will not clash.

### Work out the balance
To collect 8 fruits in 45 seconds, you need to catch a fruit every 45 / 8 = 5.6 seconds on average. If a fruit falls every 0.8 seconds, there are enough chances; but the bombs reduce the chances. Change the numbers and try: time, lives, target score, speed.

### Summary
A good game has a goal, a risk and an ending. Splitting the game into events that each do one job makes hunting for bugs easier. The countdown and `when time runs out` add time pressure. The game ends with the first `end game` block; set up the rules with that in mind and balance them by playing with the numbers.
