### What you will learn in this lesson
- How the computer works out that two pictures are touching
- The **collision event** block and the difference between `this sprite` and `other sprite` inside it
- Why the sprite's **kind** matters
- How to link several responses to one collision (deleting, exploding, playing a sound)

### What you should know first
From lesson 1, making a sprite and its position; from lesson 2, walking the player with the arrow keys; from lesson 4, giving a speed. From lesson 3, the logic of event blocks (blocks that run when something happens).

### Every sprite has an invisible box
The Game Workshop draws an invisible **rectangle** around every sprite, wrapping the filled part of the picture. If the insides of two rectangles overlap, the two sprites count as having **collided**. The empty, see-through corners of the picture do not count. This check is done 60 times a second; you only hear the result.

```
Cat box:    x = 70..86
Apple box:  x = 80..90   -> 80 to 86 is shared, there is a collision
Apple box:  x = 100..110 -> nothing shared, no collision
```

### The collision event and the two sprites
The block reads like this: "when a Player hits a Food, do these things." Inside it there are two special sprites:

| Block | What it means | In this lesson |
|---|---|---|
| `this sprite` | the one of the event's first kind | the cat |
| `other sprite` | the one of the event's second kind | the apple or the ghost |

If you want to delete the apple, you delete `other sprite`. If you delete `this sprite`, the cat disappears.

### A kind is not a name
"Player" or "Food" in the event block is a sprite's **kind**. Even if you had ten apples of the same kind, one event block works for all of them. If you choose the wrong kind, the event never runs, because there is no sprite of that kind on the stage.

### Several responses to the same collision
You can put as many blocks as you like inside the event, one under another: first a sound, then the deleting, for example. The blocks run in order from top to bottom. The `make ... explode` block is the version of deleting with sparkles.

### One touch, one response
The event runs **once**, the moment the two sprites start touching. Even if the cat is still standing on the apple, it does not run again in every frame. If they separate and touch again, it runs again.

### Summary
Every sprite has an invisible box; when the boxes overlap, there is a collision. The collision event links two kinds, and inside it there are `this sprite` and `other sprite`. To delete or explode something, you need to choose the right sprite. The event runs once, at the moment of touching.
