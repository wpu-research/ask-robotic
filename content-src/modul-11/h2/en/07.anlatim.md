### What you should know first

### The score is a number box
Inside the game there is a ready-made box called the **score**; a number sits inside it. You touch it with three blocks:

| Block | What it does | Result when the score is 2 |
|---|---|---|
| `set score to [5]` | Puts 5 in the box and wipes the old one | 5 |
| `change score by [1]` | Adds 1 to the number in the box | 3 |
| `change score by [-1]` | Takes away 1 | 1 |
| `score` | Reads the number; used in a condition | 2 |

If you write `set score to [0]` at the start of the game, every game starts clean.

### A condition is a question
A **condition** is a question whose answer is "yes" or "no": such as "is the score 3?". The `if ... do` block asks the question. If the answer is yes, the blocks inside it run; if it is no, they are skipped.

```
on collision (Player, Food):
  change score by 1
  delete other sprite
  if score = 3:
    show "You got them all!" on screen
    end game: you win
```

At the first fruit the score is 1; the question comes out "no" and the inside is skipped. At the third fruit the score becomes 3, the answer comes out "yes" and the game is won.

### Comparison signs
| Sign | What it means | When score = 4 |
|---|---|---|
| `=` | exactly equal | score = 3 no |
| `≥` | greater than or equal | score ≥ 3 yes |
| `<` | less than | score < 3 no |

If the score goes up by 1 each time, `=` is enough. But if a fruit gives 2 points, the score can jump over 3 (2, 4...). So when you check the target number, `≥` is safer.

### Sound is feedback
The `point` melody tells the player "you did it right". Sound lets you feel what happened even when you are not looking at the screen.

### Summary
The score is a number box inside the game. `set` puts in a value, `change` adds. The `if` block asks a condition and, if the answer is yes, runs the blocks inside it. To find out whether the target has been reached, `≥` is often safer than `=`.
