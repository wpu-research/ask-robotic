### What you will learn in this lesson
- How to do a job that repeats at set intervals with the `every ... ms` block
- How to make **new sprites** while the game runs and hold them with a variable
- The **random number** block and why it makes the game interesting
- Why sprites that leave the screen need to be deleted

### What you should know first
From lesson 1, making a new sprite and giving it a position; from lesson 4, giving a speed (x and y); from lessons 6 and 7, collisions and the score. You used the idea of a variable with **Create variable...** in lesson 1.

### An interval event
`when game starts` runs once. `every [800] ms`, on the other hand, **repeats** for as long as the game stays open. The time is in milliseconds: 1000 ms = 1 second, 800 ms = 0.8 seconds. So that is 60000 / 800 = 75 rounds a minute.

### Making new sprites
In each round, the `new [Apple] sprite, kind [Food]` block makes a **brand new** fruit. You put it into a variable (`meyve`, fruit) so that you can set its position and speed. The variable points to the newest fruit in each round; the old fruits keep falling at their own speeds.

```
every 800 ms:
  meyve = new Apple sprite (kind: Food)
  meyve position: x = random(10, 150), y = -8
  meyve speed: x = 0, y = random(35, 70)
  meyve delete when it leaves the world: yes
```

### Random number
`random integer from [10] to [150]` picks a number between these two numbers (including both ends) every time it runs. The fruit falls from a different place each time; the game is different each time. The screen is 160 pixels wide and 120 pixels high, so the 10-150 range is a little way in from the edges.

### Falling speed
Speed is how many pixels are covered in a second. If y is positive, it goes down (the top of the screen is y = 0). At a speed of 60 pixels/s, the height of the screen (120 pixels) is crossed in about 2 seconds.

| y speed | Time to cross 120 pixels |
|---|---|
| 30 | 4 s |
| 60 | 2 s |
| 120 | 1 s |

### Tidying up is a must
A fruit that has left the screen keeps existing even though it cannot be seen. The `delete when it leaves the world: yes` setting deletes them. If you turn the setting off, the number of sprites grows; the Game Workshop allows 500 sprites at most and gives an error when that is passed.

### Summary
The `every ... ms` block does a job again and again. In each round you make a new sprite and set its position and speed with a random number. Speed is measured in pixels per second. If you do not delete the ones that leave the screen, the sprites pile up and the game stops.
