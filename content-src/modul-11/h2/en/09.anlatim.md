### What you will learn in this lesson
- The **lives** number and its three blocks
- How several collision events run side by side in the same game
- How the `when lives run out` event changes who ends the game
- How to make danger felt with feedback (shaking, sound)

### What you should know first
From lesson 6, the collision event and deleting `other sprite`; from lesson 7, the `set` and `change` blocks like the score blocks, and the `if` block; from lesson 8, falling objects and sprite kinds.

### Lives, the score's sibling
**Lives** is a number that counts how many mistakes the player has left. It works like the score and appears on the screen as hearts:

| Block | What it does | When lives are 3 |
|---|---|---|
| `set lives to [5]` | Sets the lives | 5 |
| `change lives by [-1]` | Adds -1 to the lives | 2 |
| `lives` | Reads the number | 3 |

The lives do not go below 0. When the lives reach 0, the "out of lives" state begins.

### Two kinds, two events
The falling things are of different kinds, so you write two separate events:

| Event | Response |
|---|---|
| when a Player hits a **Food** | score +1, melody, delete the fruit |
| when a Player hits an **Enemy** | lives -1, shake the screen, boom sound, delete the bomb |

Each event only runs when its own two kinds touch. One does not spoil the other.

### Shaking and sound
`shake screen for [250] ms` tells the player "you lost a life". As the time gets longer, the feeling changes: 100 ms is a light shake, 800 ms is a long shake. The right time depends on the mood of the game.

### When the lives run out, who ends the game?
If you never write a `when lives run out` block, the game ends by itself the moment the lives reach 0 and it says "NO LIVES LEFT". If you write this block, the decision passes to you: you show your own message, and **you** must also put in the `end game: [you lose]` block. If you do not, the game carries on with zero lives.

```
when lives run out:
  show "You are out of lives!" on screen
  play melody lose
  end game: you lose
```

### A calculation
You have 5 lives at the start and each bomb takes 2 lives. The first bomb leaves 3, the second leaves 1; the third brings the lives down to 0 (not -1). So the game ends at the third bomb.

### Summary
Lives is a number that counts your margin for mistakes. Separate collision events are written for fruit and bombs. When you touch a bomb, the lives go down, the screen shakes and the bomb is deleted. If you write the `when lives run out` block, ending the game is your job.
