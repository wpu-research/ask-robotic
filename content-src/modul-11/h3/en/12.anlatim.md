### What you will learn in this lesson
- That a sprite touching a tile is caught as an event
- That the tile event runs once, at the moment of first touching
- The three steps needed to win a game: message, sound, end the game
- Why a maze has to be solvable

### What you should know first
Lesson 11: map, tile, wall box, column and row. From week 2, it is enough to know how to write a message on the screen and play a melody.

### Tiles make events too
In week 2 you ran an event when two sprites hit each other. The same idea works for tiles. The `when a [Player] sprite touches tile [Door]` block runs the blocks inside it when the player touches that tile. You make two choices in the event: which kind of sprite (Player) and which tile (Door).

### The event runs once
The tile event is triggered **at the moment of first touching**. Even if the cat keeps standing on the door, the event does not run again and again. When it comes out and goes in again, it runs again.

```
player went into the door       -> the event runs (once)
player waits there              -> the event does not run
player came out and went in again -> the event runs again
```

So if you put `change score by [100]` inside the event, waiting at the door does not raise the points.

### The three steps of winning
A player who finds the exit gets a reward and the game ends. The door event in the lesson has three blocks:

1. `show [You found the exit!] on screen`: tells the player.
2. `play melody [victory]`: a celebration sound.
3. `end game: [you win]`: ends the game.

If the last one is missing, the message appears but the game carries on.

### Maze design
The walls in the maze come from the tile set. The door tile's wall box must not be ticked, because the cat needs to go into the tile. A small cat (8 x 8 pixels) walks easily in 16 pixel corridors.

If you edit the maze, **a path to the exit must remain**. If the path is closed off with walls, the event never runs and the game cannot be won. So play the maze you changed yourself.

### Summary
The event that runs when a tile is touched is triggered once, when the sprite first touches the tile. To let the player win the game, you write a message, play a melody and use the `end game` block. Keeping the path to the exit open is the first rule of maze design.
