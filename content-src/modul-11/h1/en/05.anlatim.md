### What you will learn in this lesson
- How to plan a small game by first splitting it into a **goal list**
- How to develop a game with the run, try, fix loop
- **Feedback** effects such as screen shake, explosions and messages
- How the sound blocks (beep, note, melody) work
- How to bring several jobs together inside one event

### What you should know first
Lesson 1: stage, sprite, variable, `when game starts`. Lesson 2: key movement, stay on screen. Lesson 3: button events, talking. Lesson 4: speed, bounce, tiling.

### Split the game into goals
A big job gets easier when you split it into small jobs. This project has seven goals; each one comes from one of this week's lessons:

| Goal | From which lesson |
|---|---|
| Grass floor | Lesson 4 (tiling) |
| The cat walks | Lesson 2 (key movement) |
| The cat stays on the screen | Lesson 2 (stay on screen) |
| The star keeps bouncing | Lesson 4 (speed and bounce) |
| A: the cat talks | Lesson 3 (talking) |
| A: a sound plays | this lesson |
| B: explosion | this lesson |

Do each goal one at a time, and after each one run the game and try it. Then if something breaks, you know the culprit is the block you added last. This is called the **run, try, fix** loop.

### Feedback: let the game respond
When the player does something, the game responding makes the game feel alive. We call this response feedback. You have these tools:

| Block | Its effect |
|---|---|
| `... explosion at x ... y ...` | throws out coloured sparkles |
| `shake screen for ... ms` | the stage shakes for a short time |
| `show ... on screen for ... seconds` | shows a message in the middle |

The explosion's x value should be between 0 and 160 and its y value between 0 and 120, so that it is easy to see inside the stage. For the middle of the screen, x 80, y 60 is a good choice.

### Sound blocks
There are three kinds of sound block: `beep` (a frequency and a time, Hz and ms), `play note` (a music note such as C4 or A4) and a ready-made `play melody`. The higher the frequency, the higher the sound. An important detail: each sound block starts its sound the moment it runs; the blocks do not wait for each other to finish. If you put three note blocks one after another, the three notes do not play one after another; they play at the same time. To line notes up in order, you need timing blocks; you will learn them in the coming lessons (week 2). For now, use a single note, a single beep or a ready-made melody.

### Putting several jobs in one event
You can connect as many blocks as you like under an event. The A button can hold both the talking and the melody. But if you write two separate events for the same button, both of them run; so that things do not get mixed up, write a single event for each button and put the jobs in order inside it.

### Summary
Split a big game into a goal list, and run it and try it after each goal. Explosions, shakes and messages let the game respond to the player; explosion coordinates must be inside the stage. Sound blocks start their sound the moment they run and do not wait for each other. Write a single event for each button and put all the jobs inside it.
