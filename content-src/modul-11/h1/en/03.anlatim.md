### What you will learn in this lesson
- What an **event** is and how event blocks differ from other blocks
- Events that run when a button is pressed and when a button is released
- How to change a sprite's picture and the direction it faces
- How the speech bubble works
- How to tell continuous things from one-off things

### What you should know first
Lesson 1: sprite and variable. Lesson 2: controller, key movement and the game repeating 60 times a second.

### Event: "when this happens, do that"
So far the blocks have run in order. Some jobs, though, are only done **when** something happens. We call these **events**. `when game starts` is an event. Our new event: "when the A button is pressed".

An event block sits at the very top, like a hat. The blocks you connect under it only run when the event happens. Event blocks are not attached under another block; they stand side by side in the work area, separately. They all wait at the same time.

### Pressed and released
There are two events for every button:

| Event | When it runs |
|---|---|
| pressed | the moment you press the button, once |
| released | the moment you lift your finger, once |

Holding the button down does not run the event again and again. For continuous jobs like walking, there is the key movement block. For instant jobs like jumping, talking or shooting, you use an event.

A timeline as a sketch:

```
time:         ---->
A button:     __/‾‾‾‾‾‾‾‾‾‾\__
                ^           ^
          pressed       released
          (once)        (once)
```

### Picture, direction and talking
There are three easy ways to change a sprite:

| Block | What it does |
|---|---|
| `set kedi picture to Robot` | changes how the sprite looks; its kind and position stay the same |
| `kedi faces left` | flips the picture sideways; you do not need to draw a new picture |
| `kedi says "Hello!" for 2 seconds` | shows a speech bubble above it |

The speech bubble disappears by itself when the time is up. The game draws 60 frames a second, so a 2 second bubble is visible for 120 frames. When the picture changes, the sprite's kind does not change: the cat with the Robot picture is still a Player.

### Always use a variable
Inside events too, use your own variable instead of `this sprite`. Otherwise the sprite made last is affected. With one sprite nothing goes wrong, but the moment you add a second sprite, the bugs begin.

### Summary
An event is a block that runs when something happens; the blocks connected under it only run then. Button events come in two types, pressed and released, and each one runs once. You can change a sprite's picture, the direction it faces and its speech inside an event. Continuous jobs are done with key movement, instant jobs with events.
