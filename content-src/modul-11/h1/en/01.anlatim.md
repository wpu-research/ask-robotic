### What you will learn in this lesson
- What a game's stage and a sprite are
- How to show a point on the screen with two numbers (x and y)
- Why giving a sprite a **kind** is useful
- That a variable is a name label given to a sprite
- That blocks run from top to bottom, in order

### What you should know first
Nothing. This lesson starts from zero. You only need to be able to drag blocks with the mouse.

### Stage and sprite
Every game is played on a **stage**. The stage is the game's screen: in the Game Workshop it is 160 pixels wide and 120 pixels high. A **pixel** is the smallest coloured square on the screen. Every player or object on the stage is called a **sprite**. The cat is a sprite, and so are the apple and the enemy.

Think of the stage as a theatre stage. First the set is built (the background colour), then the actors take their places (the sprites).

### Position: x and y
Two numbers tell you where a sprite is. They are called **coordinates**.

| Number | What it shows | When it gets bigger |
|---|---|---|
| x | distance from the left | the sprite moves right |
| y | distance from the top | the sprite moves down |

The top left corner is the point x 0, y 0. The middle of the screen is the point x 80, y 60. The bottom right corner is about x 160, y 120. Watch out: y grows downwards, not upwards. It is the opposite of the graphs in your maths lessons.

A sketch:

```
x: 0 ----------- 80 ----------- 160
y=0    top left                 top right
y=60               middle
y=120  bottom left              bottom right
```

The position shows the **centre** of the sprite. If you put the cat at x 40 y 80, the middle of the cat is there.

### Kind and variable
Every sprite has a **kind**: such as Player, Enemy, Food. The kind sets the sprite's role in the game. Later, so that you can say "give a point when the Player hits the Food", the computer needs to know which one is the player and which one is the food.

The block that makes a sprite puts it on the stage, but it does not give it a name. To reach it later, we use a **variable**. A variable is a name label stuck on something. After you put a sprite into the `kedi` (cat) variable, everywhere you write `kedi` you mean that sprite.

A small example (the blocks written as text):

```
when game starts
  background color: sky
  kedi = new Cat sprite, kind Player
  move kedi to x 40 y 80
  elma = new Apple sprite, kind Food
  move elma to x 120 y 80
```

### Order matters
The blocks under the `when game starts` block run from top to bottom, one by one. First the sprite is made, then it is put in its place. If you mix up the order, you give a command to something that does not exist. A block that is not connected to this event block does not run at all.

The `this sprite` block points to the sprite made last. So that there is no mix-up when you have two sprites, use a separate variable for each sprite.

### Summary
The stage is 160 x 120 pixels. A sprite is a player on the stage; its place is given by the numbers x (from the left) and y (from the top); y grows downwards. Its kind tells you the sprite's role. A variable is the name you give a sprite. Blocks run in order, and they must all be connected to the `when game starts` block.
