### The hidden skeleton of every game
Chess, football and a computer game are nothing like each other. But in all of them the same five questions have been answered: **Who are you?** (the player), **What are you trying to do?** (the goal), **What stops you?** (the danger), **When do you win?** and **When do you lose?**

If you answer these questions before you put any blocks into a game, the chance of it being left half-done is much smaller. When the questions are written on a card, we call it a **design card**.

| Question | Space game | Cat and apples |
|---|---|---|
| Player | Ship | Cat |
| Goal | Shooting aliens | Collecting apples |
| Danger | Aliens, time | None (a ghost later) |
| Winning | Still alive when the time runs out | When the score reaches 3 |
| Losing | When lives reach 0 | When lives reach 0 |

### Counters and rules
The **score** and **lives** are the game's own counters. You write their values when the game starts: for example, score 0 and lives 3. A **rule** is an event and a condition put together: "when an apple is eaten, raise the score" is an event, and "if the score is 3, win" is a condition.

You write the winning rule yourself. If you do not write a losing rule, the game is lost by itself when lives reach 0. So every game has an ending, but you define the winning ending.

### Where should the check go?
A condition is only asked at the moment it runs. If the `if score ≥ 3` block were at the start of the game, the score would be 0 at that moment, so the answer would always be "no". It must be asked where the score changes, that is, inside the collision event.

Another trap is the difference between `=` and `≥`. If each apple gives 2 points, the score goes 2, 4, 6. If the rule is `score = 5`, the score is never equal to 5. If the rule is `score ≥ 5`, you win at 6. If the number can skip, use `≥`.

### A small calculation
Say each apple is worth 4 points and the winning rule is `score ≥ 10`. The score goes 4, 8, 12; because 12 ≥ 10, you win on the third apple. So the number of apples needed is the target score divided by the points per apple, **rounded up**: 10 ÷ 4 = 2.5 → 3.

### Summary
Every game's skeleton is made of five questions: player, goal, danger, winning, losing. The score and lives are set at the start, and rules are events and conditions put together. The win check must be inside the event where the score changes, and written with `≥` if the number can skip. Even if no losing rule is written, the game ends when lives reach 0.
