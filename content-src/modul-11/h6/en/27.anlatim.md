### What you will learn in this lesson
- How to combine three independent rules (hitting, lives, time) in one game
- How to use a **variable** like an adjustment knob for the game
- How a timed event (`every 4000 ms`) makes the game harder over time
- How to work out the difficulty increase and balance it

### What you should know first
- The game skeleton, score, lives and winning rule (lesson 26)
- The collision event: `when a [Bullet] hits a [Enemy]` and deleting sprites
- Moving with the arrow keys and the `every … ms` event (lessons in weeks 1-4)

### A game is the sum of small rules
Space defence looks big, but there is no new idea in it. Four small rules sit side by side:

| Rule | Event | Result |
|---|---|---|
| Hitting | Bullet hits Enemy | Score +10, the alien explodes |
| Lives | Player hits Enemy | Lives -1, the screen shakes |
| Time | When time runs out | The game is won |
| Difficulty | Every 4000 ms | `hiz` goes up by 5 |

Each rule lives in its own event. If you delete one, the others keep working. That is why you build a big game rule by rule, not all at once, and test each rule with ↺.

### A variable: a box that remembers a number
A **variable** lets the game keep a number in mind. The variable called `hiz` starts at 0. One event makes it bigger, and another event reads it. Because three separate places use the same box, changing what is in the box changes all of them at once.

Watch out: `change [hiz] by [5]` adds 5. `set [hiz] to [5]`, on the other hand, fixes the value at 5; it does not go up.

### How is the difficulty worked out?
The alien's speed is worked out as "a random number between 20 and 45 + `hiz`". `hiz` goes up by 5 every 4 seconds:

| Second | `hiz` | Slowest alien | Fastest alien |
|---|---|---|---|
| 0-3 | 0 | 20 | 45 |
| 4-7 | 5 | 25 | 50 |
| 8-11 | 10 | 30 | 55 |
| 28-29 | 35 | 55 | 80 |

Because the time is 30 s, `hiz` goes up at most 7 times: 7 × 5 = 35. Making this table lets you answer the question "is it too easy or too hard?" with numbers instead of a guess.

### What happens when the time runs out?
The `start countdown from [30] seconds` block starts the counter. When the counter reaches 0, the `when time runs out` event runs. If you do not write this event, the game ends as a loss. We chose the rule "survive for 30 seconds and win". An event block is not put inside another event; it stands on its own in the workspace.

### Summary
A full game is the sum of small, independent rules. A variable remembers a number, and several events can read and write the same variable. `change` adds, `set` fixes the value. A variable that grows over time makes the game harder step by step, and you can work out the increase with a table.
