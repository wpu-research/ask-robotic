### What you will learn in this lesson
- Combining all the parts of the balancing robot (reading, filter, fixed loop, cascade) in a single program
- Setting up a state machine for fall detection and a safe stop
- Expressing the success of a control system in numbers: largest tilt and settling time
- Why gains that work in the simulation cannot be carried straight over to a real robot

### What you should know first
From this week: 101 (raw reading and bias), 102 (complementary filter), 103 (fixed period) and 104 (cascade). From Module 3: a state machine with `enum` (lesson 28). From Week 1: motor direction, PWM and the dead zone (lessons 77-78).

### Every part comes from an earlier lesson
The program runs in five steps: wait for the fixed period, read and filter the IMU, update the state, run the cascade control, report the measurements. There is no new algorithm; there is putting what you learned in the right order. The order matters: deciding the state before updating the angle, or doing the control with an unfiltered angle, causes errors.

### State machine
Three states are enough:

| State | Meaning | Motors |
|---|---|---|
| DENGE | Control is running | Cascade command |
| KONTROLSUZ | Control switched off for an experiment | Off |
| DUSTU | The angle went past the threshold | Off, LED on |

The fall threshold must work in both directions: the robot can fall forwards or backwards, so the absolute value of the angle is checked. Stopping the motors on a fallen robot is a safety measure; the wheels of a robot lying down spin for nothing or throw the robot around.

### Measuring success with numbers
"The robot balances well" is a judgement. To turn it into numbers, three measures are used: the **largest tilt** (how far the robot leaned in the push), the **settling time** (the time it takes after the push for the tilt to drop below the threshold and stay there) and the **uncontrolled fall time** (for comparison). The definition of settling must be clear: in this project, if the tilt stays below 1° for 1 second, it counts as settled, and the settling time is the time until the tilt last went past 1°.

### From simulation to real robot
The gains (`KP`, `KD`, `KX`, `KV`) are specific to the robot in the simulation. On a real robot the motor power, wheel diameter, mass and battery are different. Start with a small gain: `KP` first, then `KD` when the robot starts to jitter, and the outer loop last. Estimating the position from the command is an acceptable shortcut only in the simulation; on a real robot an encoder is used. If you do not measure and subtract the gyroscope bias at start-up, the robot does not fall, but stays permanently tilted.

### Summary
The balancing robot is the combination of this week's four parts: measurement, filter, fixed period and cascade control. The state machine detects a fall in both directions and cuts the motors. Success is measured by the largest tilt and the settling time. The gains are specific to the robot; the structure is the same on every robot.
