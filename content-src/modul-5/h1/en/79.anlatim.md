### What you will learn in this lesson
- The structure of a parser that reads a letter command from the serial port and turns it into motor commands
- How to collect characters in a buffer and process the command at the end of the line
- How to decode and limit the command with atoi, toupper and constrain
- That the robot carries out the last command until a new command arrives, and the risk this brings

### What you should know first

### Designing a command language
A remote control can be a cable, Bluetooth or Wi-Fi; for the robot they are all the same thing: incoming letters. We use the Serial monitor instead of a remote control. Each command is one line: a letter and an optional number.

| Command | Meaning | Wheels (left, right) |
|---|---|---|
| W | forward | +, + |
| S | backward | −, − |
| A | left on the spot | −, + |
| D | right on the spot | +, − |
| X | stop | 0, 0 |

The number after the letter is the PWM speed (0-255); if it is not written, the default 150 is used. `W200`, `a100` and `X` are valid commands. To know that the command has finished, a line ending character (`\n`) is needed; "Newline" must be selected in the Serial monitor.

### A three-step parser
1. **Reading:** `loop()` adds the characters coming from the serial port to a `char` array (the buffer). When a line ending arrives, the buffer is a complete command.
2. **Decoding:** The first character is the command (made upper case with `toupper`, so `w` works too). The rest is turned into a number with `atoi` ("200" → 200) and limited to 0-255 with `constrain`.
3. **Applying:** A `switch` sets the PWM of the two wheels according to the command. An unknown letter gets the answer `?`.

The buffer has a fixed length (12 characters). Extra characters are thrown away; this way a long or broken line does not overflow memory. On the Uno, with its small memory, a `char` array is safer than `String`.

### Turning and time
When turning on the spot, ω = 2·v / L (lesson 76). At PWM 150 the wheel speed is about 0.19 m/s, so ω is about 3.2 rad/s, which is about 183° per second; for 90° you need roughly half a second. The time depends on the battery and the floor. For an accurate angle you will use an encoder and an IMU in the coming weeks.

### A dangerous behaviour
This parser carries out a command until a new command arrives. If you send a single `W150` and the connection drops, the robot keeps going. On a real robot this is not wanted; in the project in lesson 80 you will add stopping when commands stop arriving.

### Summary
The serial command parser collects characters in a buffer and, at the end of the line, decodes the first letter as the command and the rest as a number. `constrain` limits silly values, and an unknown command is reported with `?`. The robot keeps the last command going until the next command; a safeguard against the remote control dropping out is the topic of the next lesson.
