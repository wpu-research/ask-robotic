### What you will learn in this lesson
- Why a fixed threshold goes wrong when the light changes
- How to measure the smallest (min) and largest (max) value for each sensor
- How to calculate the threshold with `(min + max) / 2`
- How to calibrate by wiggling the robot, and the conditions for this

### What you should know first
- Lesson 14: the idea of calibration (measure, then decide based on that measurement)
- Lesson 78: below about 20% PWM (51 out of 255) the wheel does not turn
- Lesson 86: five line sensors, `analogRead` and a 0/1 decision with a threshold

### Why is a fixed threshold not enough?
In lesson 86 we chose the threshold as 512. This number is only good if the floor reads ≈ 164 and the line ≈ 860. If the ambient light increases, both the floor and the line shift upwards. Example: let the floor read 593 and the line 941. If the threshold stays at 512, the floor is counted as "line" too; the pattern comes out as `11111` and the robot cannot tell anything apart.

### Min, max and threshold
The solution: before starting work, measure the smallest value (min, floor) and the largest value (max, line) each sensor sees, and put the threshold exactly halfway between them:

```
threshold = (min + max) / 2
```

In the bright example the threshold becomes (593 + 941) / 2 = 767 and the decision is right again. In normal light, the simulation measures min 163 and max 860; (163 + 860) / 2 = 511.5, and `int` division throws away the fraction: the threshold is 511. Each sensor has its own min and max, because the sensors are not identical; that is why we keep the thresholds in an array.

### Starting values
To find the smallest, `enAz` must start very large (1023) and `enCok` very small (0). The first real reading beats both at once. If you write them the other way round (`enAz = 0`), no reading can be smaller than 0; min is never updated.

### Measuring by wiggling
To catch min and max, the sensors need to see both the line and the floor. The robot starts with the line in the middle and wiggles by turning on the spot to the left, to the right, then to the left again. Meanwhile the line passes under the sensors. Three cases where calibration goes wrong:

| Case | Result |
|---|---|
| PWM below the dead zone (for example 40) | The robot does not turn, A2 always reads 860, min = max = 860, the threshold becomes 860. `860 > 860` is false, the line is not seen. |
| Time too short (for example 300 ms) | The edge sensors never see the line, min = max = 163 stays, even a flicker on the floor becomes "line". |
| The robot starts away from the line | Max stays at the floor value, the threshold cannot pick out the line. |

Calibration is done once; if the light later changes noticeably, it must be repeated.

### Summary
A fixed threshold is only right in the conditions where it was measured. In calibration, each sensor's min and max are measured, and the threshold is calculated with `(min + max) / 2`. `enAz` starts large and `enCok` small. The measurement is only reliable if the sensors have seen both the line and the floor; so the wiggle must be done fast enough, for long enough and with a robot that starts on the line.
