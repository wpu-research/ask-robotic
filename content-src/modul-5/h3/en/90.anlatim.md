### How do the parts fit together?
The program is made of six states and moves through them in the same order on every pass:

| State | What does it do? | Where does it go? |
|---|---|---|
| `KALIBRE` | Wiggles for 1.8 s, measures min/max, calculates the thresholds | `IZLE`; if the contrast is low, `HATA` |
| `IZLE` | Bang-bang direction decision, updates `sonYon` | If there is no line, `BOSLUK` or `ARAMA` |
| `BOSLUK` | Goes straight | If the line appears, `IZLE`; if the time runs out, `ARAMA` |
| `ARAMA` | Turns on the spot towards the last direction | If the line appears, `IZLE`; if the time runs out, `HATA` |
| `BITTI` | Motors off, report printed | - |
| `HATA` | Motors off | - |

### Safety measures
Every measure has a reason. `MIN_KONTRAST = 200`: if a sensor's max − min difference is less than 200, line and floor cannot be told apart (the robot may have started far from the line); the robot is not driven and `KALIBRASYON HATASI` is printed. When `ARAMA_MS` runs out, the robot stops. The finish strip (all five sensors on the line) is only looked for 3 s after the start, so that an odd reading at the start does not stop the robot by mistake.

### Measurement
The robot measures its own performance. `kayipMs` is the total time during which no sensor sees the line; `enUzunMs` is the longest single gap. The time of each pass (`dt`) is the time since the previous pass and must be updated on every pass with `sonTur = simdi`; if you do not update it, `dt` becomes the time since the start and the loss comes out many times too large. At the finish, `BITTI sure=... kayip=... enuzun=...` is printed.

### Speed is a trade-off
When only `HIZ` is changed on the same track, in the simulation (approximate values):

| `HIZ` | Lap time | Time not seeing the line | Result |
|---|---|---|---|
| 140 | 17.6 s | 3.8 s | finished |
| 170 | 13.3 s | 2.7 s | finished |
| 230 | 8.6 s | 1.3 s | finished |
| 255 | - | - | `CIZGI KAYBOLDU`, stopped |

As the speed increases the lap gets shorter, but beyond a limit the robot cannot find the line at the sharp bend. Instead of saying "the fastest is the best", look at both the time and the loss.

### Summary
A line-following robot is a state machine: calibrate, follow, cross the gap, search for the line, finish or stop safely. Every stage has a clearly defined time limit and next state. The robot measures its own lap time and the time it cannot see the line. Increasing the speed reduces the lap time but at some point spoils reliability; the setting is found by measuring.
