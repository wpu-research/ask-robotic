### Speed is a ratio
Speed is the distance travelled divided by the time taken. With an encoder, the distance comes from ticks:

```
speed = Δticks · tick_distance / Δt
```

Δticks is the number of ticks that arrive within a **window**. If the window is 100 ms, the tick distance is 1.037 cm and 3 ticks arrived in the window, the speed is 3 · 1.037 / 0.1 = 31.1 cm/s.

### How do we take the difference?
Resetting the counter at the end of each window looks tempting, but it is risky: a tick that arrives between reading and resetting is lost. A safer way is to store the value at the end of the previous window and take the difference:

```
unsigned int s = oku(tikSol);
unsigned int d = s - oncekiSol;   // pencerede gelen tık
oncekiSol = s;
```

Unsigned subtraction gives the right result even when the counter wraps round from 65535 to 0. For example, the difference between 65534 and 3 is 5 ticks. For the time, too, use the time that really passed (the `millis()` difference) instead of writing a fixed 0.1; if `loop()` slows down, the formula still stays correct.

### Quantisation: the measurement comes in steps
The counter only gives whole numbers. In a 100 ms window, 2 ticks means 20.7 cm/s and 3 ticks means 31.1 cm/s; there is nothing in between. The smallest speed step:

```
step = tick_distance / window = 1.037 / 0.1 ≈ 10.4 cm/s
```

Even if the real speed is 28.8 cm/s, you see the measurement going back and forth between 20.7 and 31.1. At low speed this is even clearer: while the robot keeps moving, 0 ticks arrive in some windows and the measurement says "stopped".

### Choosing the window
If you make the window 500 ms, the step drops to 1.037 / 0.5 ≈ 2.1 cm/s and the measurement calms down. But the measurement is the average of the last half second; if the speed changes suddenly, it reacts late.

| Window | Step | Response |
|---|---|---|
| Short (100 ms) | Large, wobbly | Fast |
| Long (500 ms) | Small, calm | Delayed |

In engineering this is a compromise: a control system based on speed reacts for no reason to a wobbly measurement, and reacts late to a delayed one.

### Summary
Speed is the number of ticks in the window times the tick distance, divided by the window length. The counter is not reset; the previous value is stored and subtracted, and the time is really measured. Because the counter gives whole numbers, the speed comes in steps; the size of a step is the tick distance divided by the window. A short window measures quickly but wobbles, a long window measures calmly but with a delay.
