- Writing a test matrix: the expected column first, then the measurement
- Using `millis()` and a state start time instead of `delay()` in a state machine

### A decision layer on top of the subsystems
The PID in lesson 112 made no mistake; it simply did not know anything called "no target". Subsystems do the work; the state machine decides **which one runs when**. The rule is simple: in each state a single behaviour runs; every condition for the transitions between states comes from a sensor or from time.

A piece from path A:

```
CIZGI_IZLE -> (line seen, then no line for 300 ms)    -> SERBEST
SERBEST    -> (obstacle closer than 28 cm in front)    -> SOLA_DON -> YANA_GIT -> SAGA_DON -> SERBEST
SERBEST    -> (all three sensors on a line at once)    -> BITTI
```

The turn and sideways times are counted with `millis()`. If `durumBasla = millis()` is not written at every transition, the next state ends at once, because the old timestamp has long since run out.

### A safe default
In path C, when the target disappears the motors stop **at once**; when the counter reaches 8 (about 0.5 s), the KAYIP (lost) state is written. The counter only counts empty measurements in a row; a single full measurement resets it. When the target comes back, the PID's integral and old error are reset; otherwise the old values throw the robot at the new target. The same PID, with a single difference (the decision layer), brought the 38 cm run down to 0.8 cm.

### Test matrix
A table: each row is a scenario; the columns are the expected and the measured result. **The expected column is written before measuring.** If you write it after measuring, you talk yourself into the result. A single scenario that works is not proof; rows are added by changing things such as the starting position, a weaker right motor or the speed of the target.

In path B the test takes another form: so that the arm's tip does not jump, each joint moves at most 1.5° every 20 ms. That is why a 90° movement takes at least 60 steps, that is, 1200 ms.

### A tuning value does not carry over
Path A's `KP = 55` value was found on a set-up with line sensors 2.0 cm apart. In the arena the sensors are 2.4 cm apart; the same position value stands for a 20% larger deviation and the correction is too harsh. The gain is reduced in the same proportion: 55 / 1.2 ≈ 46. General rule: if the set-up changes, the tuning is measured again; do not copy a number from another set-up.

### Summary
A state machine combines the subsystems: a single behaviour in each state, transitions from sensors or time. When you are not sure, stop the motor; reset the timer at every transition. The expected column of the test matrix is written before the measurement and contains more than one scenario. One set-up's tuning value does not carry straight over to another set-up.
