### Split it up and measure
If a three-hundred-line program spins on the spot the first time it runs, the culprit could be the motor, the sensor or the decision logic. If they are all tangled together, you cannot tell them apart. The solution: make each job a **subsystem**. A subsystem has these three: a function that does a single job (for example `surus(sol, sag)`), a way of running it on its own (a serial command) and a pass condition written in numbers.

### Path A: drive, distance, line
- **Drive:** below 20% of the PWM (51), the wheel does not turn. `motor()` rescales a non-zero command between 51-255: `map(abs(hiz), 1, 255, 51, 255)`. If the command is 128, the output is 153.
- **Distance:** the HC-SR04 gives a time. Distance (cm) = time (µs) / 58. 1160 µs is about 20 cm. If there is no echo, 400 is returned ("very far").
- **Line:** the numbers of the five sensors become weights: A0 = +2, A2 = 0, A4 = -2. The position is the average of the sensors that see the line. If no sensor sees it, the position is meaningless; the code tells this apart with `sayi`.

### Path B: inverse kinematics and the servo driver
The reach of an arm whose two parts are 10 cm is 20 cm; for a target further away, the cosine value goes past 1 and the function returns `false`. In the Servo library the angle is converted to a pulse: us = 544 + angle × 1856 / 180. For example, 1008 µs for 45°. For the target (10; 10), shoulder 90° and elbow 90° are found.

For checking, a **round trip** is used: feed the angles you found back into forward kinematics; if the resulting point is the same as the target, the formula is right. This is a cheap way to test a function without calculating by hand.

### Path C: distance PID
The error is the measured distance minus 20 cm. The output is `u = KP·hata + KI·integral + KD·türev` (error, integral, derivative). The measurement first goes through the **median** of three values, because the derivative amplifies noise. The integral is limited (windup), and if it is closer than 0.5 cm to the target, the robot stops (dead band).

The known limit of this subsystem: when the target suddenly disappears, the measurement comes in as 400 cm and the PID says "the target is very far away, go". The robot rushes about 38 cm forwards. The fault is not in the PID but in the **missing decision layer**; its solution is in lesson 113.

### Summary
A subsystem is a part that has a single job and is tested on its own. In path A you build dead-zone rescaling, distance from echo time and the line position; in path B the reach, the servo pulse and the round-trip test; in path C a PID with a filtered measurement. Each subsystem carries its own pass condition in numbers; no untested part goes into the combined robot.
