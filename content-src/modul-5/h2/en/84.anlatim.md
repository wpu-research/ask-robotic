### Why a state machine?
If you write the three skills from lessons 81-83 one after another with `delay`, the robot cannot look at anything while it waits. For example, if a bumper is pressed while it is turning, nobody notices. The solution: give the robot **a single state** at any moment, and in each state answer the questions "what am I doing, and when do I stop?".

### Five states
| State | What it does | Exit condition | Next |
|---|---|---|---|
| ILERI | Drives straight | Distance < 25 cm, or a bumper | DUR / GERI |
| DUR | Switches the motors off, waits 250 ms | 250 ms are up | TARA |
| TARA | Looks in 5 directions | 5 measurements done | DON / GERI |
| DON | Turns on the spot | The turning time is up | ILERI |
| GERI | Goes backward for 400 ms | 400 ms are up | DON |

This table is the skeleton of the program. Draw the table before you write the code: every row must have an exit, otherwise the robot stays in that state forever.

### No delay, but a time check
In each state the check `simdi - durumBasi >= SURE` is made. `durumBasi` is the `millis()` value at the moment you entered that state. If the time has not run out, `loop()` returns without doing anything and checks again on the next pass. That is why `loop()` runs hundreds of times a second, and in ILERI you can check the bumper on every pass.

The state is changed by these three lines: `durum = yeni; durumBasi = millis(); Serial.println(...)`. If you write this by hand every time, you will forget `durumBasi`. So you write a `gec(yeni)` function and change the state **only with it**.

### Why is the bumper still needed?
The sensor is a single beam. The beam can pass through a 3 cm slit in a wall, and the robot does not see the obstacle. The bumper catches this: in the ILERI state the bumpers are checked first on every pass. In the simulation, at such a slit both bumpers were pressed and the robot got away in the order ILERI → GERI → DON.

### Getting stuck
If even the farthest direction in the scan is closer than 35 cm, the robot has gone into a pocket. Instead of trying to turn, it first goes to GERI and then turns. This way you reuse the existing states without writing a separate state for this case.

### Summary
A state machine puts behaviour into a table of states, exit conditions and transitions. Because `millis()` is used instead of `delay`, the robot can check the bumpers and commands on every pass. Change the state with a single `gec()` function. The bumper is a backup for obstacles the sensor cannot see, and the stuck check is a backup for cases where the scan result is no help.
